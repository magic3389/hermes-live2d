# 2D 傀儡模型绑定（Iki = Live2D 的开源替代）

## When to Use

要把立绘做成会眨眼、张嘴、转头、能被语音驱动的 2D 角色（桌宠、分身 App 形象、vtuber），
但不想碰 Cubism 授权。成品是 `.iki`（JSON），播放器 80KB，不背编辑器。

本机路线：开源 **Iki**（`refs/iki`：`packages/engine` 播放、`packages/format` 校验、
`packages/editor` 编辑器、`packages/mcp` 切层/绑定）。

**管线已脚本化**，通用脚本在
[`github.com/magic3389/hermes-live2d`](https://github.com/magic3389/hermes-live2d)：

| 脚本 | 作用 |
|---|---|
| `pipeline/matting/rmbg_cut.py` + `extract_subject.py` | 抠图（背景有干扰时）→ 剔碎片 → 居中正方白底。**模型默认 BiRefNet**，RMBG 只当备选，见 `references/matting.md` |
| `pipeline/run_seethrough.sh` | See-through 拆层 → 17 层 PSD（约 7 分钟） |
| `pipeline/postprocess.py` | 清底膜 · 分区换色 · 合层 · 补洞 · backdrop · 语义层序 · 几何归并（`--skirt-zone` / `--sleeve-band` / `--reclaim-hand`）|
| `pipeline/add_warp.py` | 布料/尾巴/长发 matrix→warp：`--bend-zone` 限定弯曲区间、`--amp` 直控摆幅 |
| `pipeline/split_part_deformer.py` | 给单层换独立 deformer 限幅（如不拆腿时给 `legs` 一个 ±4px 的）|
| `pipeline/auto_split_legs.py` | 双腿全自动拆分 |
| `pipeline/build_iki.py` | PSD → `.iki`，枢轴全部由 bbox 推导 |
| `pipeline/add_warp.py` | 裙子/布料从 `matrix` 刚体换成 **`warp` 网格弯曲**（铁律 25；参数范围自动读，摆幅按 part 宽度取）|

换一张完全不同的立绘，这六个脚本**不用改任何常数**。其中 `add_warp.py` 是在 `build_iki.py`
之后单独跑的一段（也可以合并进绑定器）；不做这一步，裙子就是绕一个点转的木板。
完整流程与三例实测数据见 `references/pipeline.md` 与仓库 `docs/01_pipeline.md`；
已知问题与可修性边界见仓库 `docs/04_known_issues.md`。

## 先分清素材，别把能力说大

| 素材 | 能做到 | 入口 |
|---|---|---|
| 命名分层 PNG（face/eye_L/mouth…）或分层 PSD | 全套绑定：眨眼、张嘴、头转、视线、物理摆动，秒级 | 编辑器「导入图层组」 |
| 单张成品图 | 整张作为一个部件：能摆位、能整体变形，**不会眨眼张嘴** | 「导入单张图片」 |
| 单张成品图且要会动 | 必须先切层；切层**不含 ML** | See-through 出 17 层 PSD |
| 要求「被刘海遮的额头、眼睑下的眼白也完整」 | 单图切层做不到；生成式拆件只补到 **36–54%** | 同上，但不承诺全补 |

**已有 See-through PSD 时先复用**：工程里躺着 `out/layerdiff_output/*.psd` 就是可用上游资产，
另起一套单图切层等于丢掉已付成本，换来层数更少、还带层缝的结果。开工先 `ls` 一遍。

### ⛔ `@ikijs/mcp` cut 管线只算调试件

按颜色 + 形态学硬切，稳定只出 **14 层**（`face/nose/mouth/eye_*/iris_*/lash_*/hair_front/hair_back/body`）。
不认识四肢、不认识尾巴，头发只有前后两层，每层像素硬切互不重叠。用户会直接判「还不如上一个 live2d」。
**要交「会动的模型」时先自检**：头发 / 眼白 / 虹膜 / 睫毛 / 眉 / 嘴 / 上衣 / 手 / 腿袜 / 鞋 / 尾巴
各自独立成层吗？有一条答不上就直接上 See-through。

### 「原图」= 未经任何处理的原始立绘

用户说「原图」时指的是**最原始那张立绘**——可能带背景渐变、装饰外框、其他头像、标题文字，
体积和尺寸都是原始的（例：1858×3178）。

**不是**你为了喂管线做的中间件：抠图后的、居中补白的、缩放到 1280 的版本。

这条决定排查时三样东西落在哪：**标记图、裁切范围、对比基准**。拿中间件顶替会被当场纠正
（「原图指的是没有 live2d 化之前的原图」）。而且中间件已经过抠图与缩放，投影和背景早被改过一次，
原始问题（哪块被误判成前景）在它上面根本看不出来。

同理，用户指着一张图说缺陷时，先确认「这张图是哪个模型的渲染、用的是哪份素材」，再开始量。

## 26 条铁律（细则见 references）

1. **分离/切割的基准必须是未处理的原始层**，不能拿自己上一版产物当基准（会循环论证）。
2. **「某层上多了东西」先查谁盖在它上面**，再查这层自己的像素。已多次同一模式：脖←上衣、耳←头饰、腿←裙子、腰←围裙、手←上衣。
   **修法看「是谁盖的」分两种**：
   · **语义层溢出**（脖/耳/腿/腰那种）⇒ **挖空，不是换色**。换色只改 RGB、alpha 还是那层自己的形状，
     会继续盖住下层；挖空（alpha=0）才能让下面带正确颜色的层露出来。判据：原图该处偏暗（均值 <140）而本层偏浅（通道差 >40）。
   · **自己的画序排错**（手 / 手持物排在衣服之前）⇒ **改 `ORDER`**，把 `objects`、`handwear` 压到 `topwear` 之后。
     在这里挖空会让手彻底消失。`objects`（捧着的杯子这类手持物）不在 ORDER 表里时会被按面积甩到最顶层，
     症状是「杯子悬空、和手断开」。详见 `references/rigging-rules.md` 第 46 条。
3. **判断「两个部件有没有真分开」必须两个数一起看**：参数相关 < 0.85 **且** 接缝宽度 ≈ 原图。
   只看一个必然调错方向（看缝→改同源→融合；看相关→改异源→撑缝）。
4. **不要用 alpha 羽化消接缝**。两层颜色掺混（`a=0.5` 时各掺一半）会让它们**视觉上融合成一条**。
   接缝靠**重叠带宽**解决。
5. **「部件不动」先调奥行き / 物理 `scale`，拆层是最后手段。** 连续整块 = 一个 part，绕根部转，不拆段
   （拆段必错位露缝，绑同一参数又变刚性整体）。
   ⚠ **幅度按「像素位移」标定，deformer 和 physics 两头都得给足。** deformer 的 `from/to` 是**像素**，
   physics 的 `scale` 决定参数能走多远；不配套时参数在动、画面不动。实测腿 `translateX ±3` + `scale 8`
   ⇒ 参数只到 **±0.06**（≈0.5px），用户判「腿脚没动」；改 `translateX ±9` + `scale 38` ⇒ 参数 **±1.95**
   （≈±17px），帧间腿区变化 43,527px。参照系：头部 `translateY` 本来就是 ±10，同量级才看得见。
   摆幅上限看「会不会撑开部件间隙」：**整体平移不改变两腿相对间距**，所以平移可给 ±9；
   绕根旋转不行 —— 350px 长的腿转 1.3° 就让脚踝横移 8px，把 1px 缝拉成 19px。
6. **前发 / 后发 / 呆毛不能拆**。切口露的是**下一层内容**（脸皮、后发），不是透明背景，
   所以「透明底量缝」查不出来、补边也救不了。
7. **切之前先数连通域**：1 个连通域 + 无颜色分界 = 没有可切的结构，任何切线都是自己画的。
   细分只有两种合法依据：**连通域**、**颜色/语义**。按坐标切一律被用户点破。
8. **`PSDImage.new(mode="RGBA")`**。`mode="RGB"` 会让每层 alpha 静默变 255，
   症状是「只有最上面几层有物理」，极易误判成「工具不支持那些部件」。
9. **层序按语义画序写 PSD（先写=在下）**，不能按面积排。实测合成差 28.03 vs 5.30。
10. **`psd.composite()` 不是原图**（偏亮约 25）；颜色源必须 `Image.open(原图)`。
    但也不能整张无条件替换——各层 alpha 有溢出，会拖出别人的身体。判据：本层色 ≈ 原图（差 ≤60）才换。
11. **层 `topil()` 尺寸 ≠ 画布**（可带 offset 或被裁切），必须按 `l.offset` 贴回全画布。
12. **See-through 底膜（alpha 1–60 铺满画布）必须清零**；**整块漏层**要加画序最底的 `backdrop` 兜底层。
    **`backdrop` 的量同时是上游抠图的健康指标**：它统计的是 See-through 认不出归属、被兜底补进来的内容。
    同一张图实测 RMBG 输入 7,779px → BiRefNet 输入 **2,166px**；错误补漏输入 157,197px → 修正后 **36,296px**。
    `backdrop` 上万就回抠图阶段查，**不要在后处理里加补丁**——它是喂进去的图本身带背景的放大镜（见铁律 20）。
13. **像素验收四要素**：1:1 原生尺寸 · 屏蔽背景（只算两边都有内容）· 关缓存 · cache-bust 不能覆盖 `?nodrive=1`。
    判定看数字不看 VLM（它会把原图本就有的描边当成「多余的线」）。

    ⚠ **改完先量「新产出 vs 上一版」的差：差为 0 就是改动没生效，不要往下验收。**
    后处理里加规则最典型的失败不是报错，而是判据一次都没命中（条件写反、量纲不符、
    目标层根本没有可改的像素），脚本照常打印「合成差 6.51」、不报任何异常。
    实测给「归位时连目标层的半透明内容一起顶掉」加完代码重跑，新旧渲染逐像素差 **0**
    （`(abs(a-b).max(2)>8).sum()`），那段代码一行都没被执行到。
    不先比这一下，就会把「画面没变」当成「修好了」交付给用户。

    ⚠ **VLM 对同一张图会给出相反结论。** 同一份渲染，按「有缺损吗」问判「袖子缺损、
    偏灰半透明」，换成三格并排问「右侧有什么」又判「完整、与原图一致」。
    所以它只能用来提示「该看哪儿」，结论必须回到像素数与色差；
    两者矛盾时报数据、直接把成对放大图交给用户判，不要替他在两个 VLM 结论里选一个。

    ⚠ **像素探针的落点先自检「这块该是什么颜色」，扫出来不对就是坐标错了，立刻重定位。**
    在袖子区取一条竖线扫 y 500→770，结果全程是头发色与背带色、没有一处白 —— 说明这条线
    根本不在袖子上，之前几轮「该区色差 0、所以没问题」全是在错位置得出的结论。
    做法：先明确「这块应该是白色泡泡袖」，扫到非白就停下、出放大图 + 候选色块 bbox 重新定位，
    不要继续在错误坐标上算差值并向用户汇报「差 0 是对的」。

    ⚠ **VLM 在缩略裁剪上会漏掉真实的形变。** 同一对帧，像素显示裙子区变化 26,137px、
    集中在裙摆下缘与褶皱，VLM 对放大裁剪却判「完全没变」。判「是弯曲还是平移」**看两帧差分的
    空间分布形状**：红色沿裙摆下缘呈**弧形条带** = 弯曲；整块同量位移 = 刚体。
    给用户出图时把差分热图放第三格并配文字标签，别只给两张肉眼难分的对照图。

    ⚠ **不要拿 VLM 报的坐标当定位依据。** 问「手在哪」，它给 `x690-745 / y475-540`，
    而原图那片的主色是 `(96,72,96)` **深紫衣料**，真正的皮肤像素在别处 ——
    按这个位置修了四轮，每轮都「色差很小、所以没问题」，实际一直在修衣服。
    VLM 只用来提示「该看哪儿」，**坐标必须从原图的颜色类分类算出来**：
    肤色 `R>B+18 & 140<mean<235 & min>90`、白袖套 `min>150 & mean>170`、紫发 `B≥R-12 & R-B<32 & min<145`。
    先打印候选 bbox 与主色，确认「这块该是什么颜色」再动。

    ⚠ **量「某个 part 位移了多少」不能用整行列重心。** 同一行里的其他部件（腿、脚、尾巴）
    会把重心拉走：实测裙摆重心给出 −10.9px「在动」，而同帧逐行边缘全部 +0「没动」。
    正确做法是**在该 part 自己的 bbox 内**逐行取最左/最右非白像素；行也不能取到 bbox 之外——
    裙子可见范围由它自己的 bbox 决定（`y[108,918]`），再往下的行量到的是腿和脚。
14. **See-through 的语义分类不可靠，这是管线边界不是绑定 bug**：垂下的长发/袖口会**错归**
    （c07 实测 1466px 深蓝发给 `handwear`，`front hair` 的 bbox 只到 y=288），
    上层还会用**自己那块的平均色**盖住下层正确颜色（三图实测 3879–6051px）。
    看到「颜色变浅 / 丢了一缕 / 某块不跟头动」先查这里，再动绑定。
    ⚠ **写「这块不是头发」的判据时必须拿原图比，不能拿该层自己的 RGB 比。**
    层里那块的 RGB 早被 See-through 涂成发色（这正是要抓的错分），用层色算差值永远接近 0，
    规则会一次都不触发、还不报错 —— 表现为「代码看着对、日志没这行、画面没变化」。
    正确形态是 `dif = |原图 − 该层主色|` + 「原图该处是浅白/肤色」两条同时成立，
    再把像素从该层挖掉还到上层（实测搬回 15,825px 白袖子）。
    ⚠ **前发会以半透明形式盖住同样的东西。** `topwear` 里袖子像素 alpha 255、颜色正确，
    但 `front hair` 在该区有半透明发色叠加，最终可见色被冲成 `(205,207,232)`（原图 `(244,239,245)`）——
    于是「topwear 明明有内容」与「画面上看不见」同时成立。
    判「这块最终该显示什么颜色」不能只查拥有它的那层，**要按画序从底到顶合成一遍，看谁最后落色**：
    逐层 `fill = (~covered) & (alpha>200)` 累加，得到的才是画面真值。
15. **截图/验证之前，先确认「你要截的那个页面」加载的是哪个模型文件。**
    同一个播放器常有多套入口：`main.ts` 走 `/model03.iki`、`standalone.html` → `src/standalone.ts` 走
    `/model_hand.iki`（`?model=` 可覆盖）。新版只部署给其中一个，另一个仍是旧文件 ——
    于是「我已经改好了」和「用户看到的没变」同时成立，还会拿旧模型的渲染去分析**另一张素材**，整轮方向全错。
    做法：`md5sum` 比对各 `.iki` 与 `public/` 下的文件；页面加载后读 `window.model.name` 确认；
    部署时两个入口都覆盖。缺文件时 fetch 拿到的是 HTML，报的错是 `Unexpected token '<'`（不是模型坏了）。
    **用户指着我刚发的某张图说缺陷时，只查产出那张图的模型。** 不要先去扫“整个工程里哪个模型数字更难看”
    再转去修它——工程里常并存 c04/c15/c07 三套，它们的缺陷各不相同，改错对象会让整轮白做。
    先固定「图 → 源文件 → 模型」这条链，再开始量。
16. **浅蓝投影 = 背景残留，不是「缺内容」。** 脚与脚之间、尾巴与裙子之间常有一块浅蓝，
    用户会描述成「没裁切干净 / 保留了一部分原图背景」，不要去找缺失的图层。
    判据：**亮度 >175 且 B>200 且 B−R>30**。两层都要清：`backdrop` 不补（3,898px）+
    语义层（legs / bottomwear / tail / handwear / topwear）挖掉（9,217px）—— 只清 backdrop 不够，
    See-through 早把脚间投影并进 legs 了。
    ⚠ **绝不动 back hair / front hair / headwear，并排除 y<200 的头顶带**：浅蓝发梢满足同一个颜色条件，
    误伤就缺一块头发。根因在抠图：RMBG 只输出 0/255，把投影一起判成前景。
    **真正的解是换抠图模型（铁律 20 / `references/matting.md`），不是回抠图阶段调 alpha matting**；
    这些后处理补丁从头到尾都在替坏输入擦屁股，输入干净后它们应该一次都不触发。
17. **「某侧头发明显比另一侧少」用 hair 层左右像素数比值判，比看渲染图快得多。**
    `back hair` 左 18,938px / 右 91,340px ≈ **4.8 倍** ⇒ 垂下的长发被判给了衣服层
    （实测躯干左缘 `bottomwear` 占 90.8%、中线附近 `handwear` 80.9%）。
    补回要三条同时成立：**①原图该处是发色（B>R+20 且 B>100 且均值<190）②被衣服层覆盖
    ③该衣服层在此处的色与原图差 >40**。第③条是关键——差小说明它换过色、显示本来就对，挖了反而错。
    入口 `postprocess.py --reclaim-hair x0,y0,x1,y1`，动作是「衣服层 alpha=0 → back hair 取原图」。
    纯颜色判据分不开同色衣服与头发，**必须给区域框**；补完 4.8→2.3 倍（姿势本身不对称，不会到 1）。
18. **某层「半透明 + 错色」会让那块内容发暗/消失，alpha 要和 RGB 一起修。**
    这是独立于「被上层盖住」的第三种机制：层自己拥有这块像素，但只有 alpha=73、RGB 又是别处的深色，
    渲染时深色被背景冲淡 → 视觉上就是「头发不见了」，而像素均值几乎不变（差值只有 6）。
    实测原图浅蓝发丝 `(185,213,245)`，层给 `alpha=73 RGB(36,41,49)`，渲染成灰暗一团。
    判据：**0 < alpha < 250 且本层色与原图差 >40 且原图非白** → alpha 抬满 255 + RGB 取原图（实测 13,812px）。
    只动「半透明且色差大」的像素，正常抗锯齿边缘色差本来就小，不受影响。

    ⚠ **同一机制还有 alpha=255 的版本，只查半透明会整块漏掉。** See-through 也会给出
    **完全不透明但颜色完全错**的像素，且常落在 order 更高的层上，直接把下层正确内容盖成色块。
    实测 `bottomwear` / `handwear` 在原图浅色处带深蓝黑 `(36,35,66)`、alpha=255，把腿和鞋尖盖成深色 ——
    用户报「腿部边和鞋尖的杂色块」，而在**抠图输入图**上按「深色 + 贴白 + 无描边」找只有 54px、块数 0：
    **输入是干净的，脏的是拆层结果**，所以这类问题不要在抠图阶段查。
    判据单独一档、比半透明那档更紧：**alpha ≥ 250 且色差 >90 且原图平均亮度比本层高 55 以上**
    （收紧是为了不误改正常阴影）。动作同上：RGB 取原图、alpha 保持 255。
    定位入口：拿渲染图与原图做「**原图浅、渲染深**」的差（`ref.min>150 & render.min<140`），
    再逐层查那几块是谁画的，比在全图上找杂色快得多。

    ⚠ **光靠亮度差一定会连着正常暗部一起抹平，必须再加一道「颜色族」闸门。**
    同一张图三版判据实测的权衡（全图差异 / 目标块 / 副作用）：

    | 判据 | 目标块 | 副作用 |
    |---|---|---|
    | 差>90，不限色 | 修得最干净 | **裙摆交界被抹成灰白**、出现橙褐锯齿 |
    | 差>120 + 亮度>135 | 目标块退步 | 副作用减轻 |
    | 只要「暖色皮肤」（R≥B−5） | **目标块反而变差** | 裙摆完美 |
    | 差>90 + **排除冷色**（`B ≤ R+15`） | 目标块 OK | 裙摆**逐像素一致** |

    结论：**错色块总落在暖色（皮肤）上，正常暗部（裙摆、深蓝衣料）是 `B>R` 的冷色**。
    用「非冷色」当闸门，两个目标同时满足。这套闸门是在「谁该被改」说不清时最省事的分离轴——
    比调亮度阈值有效，因为亮度在这两个目标上是重叠的、颜色族不重叠。
19. **判「人物全身范围」时，边缘屏障 flood 只能用在没有装饰框的图上。**
    Sobel 梯度当屏障、从画布四边 flood 找「与外部不连通」的区域，遇到**相框式 / 装饰外框立绘**
    会整体失效：外框是闭环，flood 进不去 ⇒ 整张图被判成人物（实测 92–98%）；
    把种子挪到「框内四角」采到的又是外框本身的深色；换成「单一背景色迭代扩散」时，
    浅蓝渐变与框外白色差太大，只扩到 1.9–8.2% 就停。
    这类图不要自己造识别器，**换抠图模型**（铁律 20）。曾据此走「RMBG 出前景 → 轮廓内部按
    『局部无边缘 + 浅色』剔投影」，被用户当场否掉：发丝高光同样又浅又平滑，这条判据分不开投影与真头发，
    会把真头发标成多余。纯线条法在带框图上做不到，别在这条路上连试四轮。

20. **抠图模型是这条管线唯一的根源杠杆：RMBG-1.4 不够用，默认上 BiRefNet。**
    浅色发丝 vs 浅色背景、带装饰外框的立绘，RMBG-1.4 会成片漏选，后面怎么补都对不齐。
    同一张 1858×3178 立绘实测：耳侧垂发 RMBG **7.3% → BiRefNet 100%**，左侧长发 **39.9% → 74.6%**，
    脚间空隙 RMBG 100%（整块判前景）→ BiRefNet **44%**（正确剔掉），推理仅 **1.3 秒**（3080）。
    用户口径：「准确率高达 99%」。
    **听到「某侧头发缺失 / 背景没裁干净」先问「这次抠图用的哪个模型」，不要先去后处理里加补丁。**
    装法、fp16 dtype 坑、补发尖配方见 `references/matting.md`。

    ⚠ **同一环节的第二个坑：补漏（找回模型漏掉的发尖）在复杂背景下会反向吃掉背景。**
    补漏判据「与本区域背景色差 >6 且紧邻前景」只在**纯色 / 简单渐变背景**成立（白底、浅蓝渐变都对）；
    背景本身是深色场景 / 壁炉 / 装饰物时，整圈背景都落在「与采样背景色差大」里，被成片补进人物。
    实测深色圣诞场景立绘补进 **67,463px 棕褐背景**，而模型对这些像素的概率只有 **0.7**——
    模型明确判背景，是补漏强行加回来的。症状是「人物边缘一圈背景」/「那一圈还是不对」。
    **跑完补漏必查**：`sus = fg & (soft < 50)`，量 >5,000px 或单块 >20,000px 就是补错了；
    修法是 `--no-fill` 只信模型原始输出（实测削掉 79,887px 背景、人物本体完整）。
    先采样四角判背景复杂度再决定补不补，别默认开补漏。

21. **拆腿不是每张素材都能做 —— 先验「有 legs 层吗」「两腿分开吗」，再跑脚本。**
    三个前置量：①`legs` 层是否存在（腿被长袜/裙子盖住大半时 See-through 只给 `legwear`，没有 `legs`）
    ②`legs` bbox 宽度占画布比例 ③拆分后左右像素比。实测三种结论：
    · 站姿分开（bbox 宽 243px ≈ 19%，左右 37,277 : 39,721 ≈ **1.07**）→ 拆对，红绿各一条完整腿
    · 坐姿交叠（bbox 宽 956px ≈ 75%，左右 144,726 : 75,129 ≈ **1.9**）→ **拆错**，红只盖弯曲的左腿、绿只盖伸出的小腿
    · 无 `legs` 层（只有 `legwear` + `objects`）→ 无从拆
    **判据：左右比 >1.5 或 bbox 宽 > 画布 50% 就不要拆**，用整块 `legs` 小幅摆，
    并在交付时明说「腿不再独立动」，不要靠补画两腿空隙来硬拆。
    验拆对没看 **`(L&R).sum()` 重叠像素**（正确时仅 56px、最大块 30px），**不要看黑底 vis 图**：
    VLM 会把轮廓锯齿读成「绿色侵入左腿 / 左腿内侧有缺口」，与像素数据矛盾时以像素为准 ——
    据此返工只会把拆对的改坏。

22. **「这块看着透明 / 发虚」有六种互斥成因，按顺序查，别在同一处反复加补丁。**
    ①层自己半透明（`0<alpha<250`，铁律 18 前半）②层不透明但色全错（铁律 18 后半）
    ③**像素归属和颜色都对，但挂在错误的 deformer 上** —— 动态时跟着别人的部位一起摆
    ④**描边被漏掉，挖空后露出后层** ⑤**变形层级链断了**（铁律 26）—— 用户指着手说「透明」，
    实际是头没挂身体、体动头不动，脖子整片错开
    ⑥**该部位根本不在任何层里** —— 被劈散到别的层、甚至整块没有任何层拥有。

    ⑤ 与 ③ 的修法不同：③ 是把像素搬回归属层（**挖空 + 把 RGB 补给该层**，不要只把颜色改成原图色 ——
    换了色仍挂在原 deformer 上，一摆就错位，比原来更难看出问题）；⑤ 是补 `parent`，不动像素。
    **先查 ⑤（10 秒，打印 deformer 的 id/kind/parent 即可）再查像素** —— 层级断着的时候像素怎么修都会露白。

    ③实测：白泡泡袖像素同时存在于 `bottomwear` / `handwear` / `topwear` 三层，颜色、alpha 全对，
    但 `bottomwear` 挂 `def_Skirt`（裙子物理 ±2.7°），一摆袖子就跟着飘，用户判「胳膊是透明的」。
    **纯静态渲染量不出来**——静态与原图逐像素差 0，必须**驱动身体摆到极限再比两帧**
    （`ParamBodyAngleX ±10` + `ParamBodyAngleZ ±6`，看袖带运动量是否异常高于相邻躯干）。
    修法：按**人体结构**划带（肩 x → 腕 x 线性插值、y 从颈底到腕线、左右各 half 宽），
    把该带内 `bottomwear` 的浅色像素挖掉（实测 30,348px）——`topwear`/`handwear` 已各有完整覆盖，
    挖掉不会露底。**这道题颜色判据彻底失效**：白色女仆装三层的「主色」都是白色
    （`(245,235,235)` / `(234,227,233)` / `(250,238,242)`），「与本层主色差 >40」选不出任何一个像素。
    用户的提示原话就是「根据人体结构判断哪一块是袖子」——同色服装只能靠解剖位置分，不能靠色差。

    ④实测：袖带内深色勾线被 See-through 漏掉，挖空 `bottomwear` 后露出后面头发
    （原图 `(68,75,122)` 描边 → 渲染 `(126,137,197)` 发色），视觉上同样读成「透明」。
    修法：袖带内**原图深色**（`min<145`）的像素强制补进 `topwear`（RGB 取原图、alpha=255），实测 27,723px。

    ⑥实测：一张双手叉腰的立绘，用户连报两轮「右边的手透明 / 看不到手」。按原图色类查手区，
    那只手的像素被**三处分摊**：`handwear` 3,060px + `bottomwear` 7,359px + **没有任何层 3,444px**。
    而 `handwear` 自身的像素、颜色、枢轴全对（层内肤色点色差 **2.4**、该区 100% alpha=255），
    于是「静态与原图平均差 2.3、合成差 1.68」和「用户看不到手」同时成立 ——
    缺的是那 3,444px，它谁都不属于，静态色差再小也量不出来。
    **判据是左右对称性，不是和原图比色差**：`handwear` 左 26,007 / 右 11,814（比值 **0.45**），
    姿势本身对称 ⇒ 一侧丢了。这与铁律 17 量头发是同一条尺子，**手 / 袖 / 腿 / 发都适用**。
    修法：几何框内把别的语义层挖空 + 把原图色写进目标层，入口 `--reclaim-hand x0,y0,x1,y1`
    （`--reclaim-hair` 同族；收回后左右比 0.45 → 1.09）。纯颜色分不开白袖套与白上衣，**必须给框**。

    **排查顺序**：先跑两帧差分判「是不是只在动态错」（是 ⇒ ③），再对静态渲染量 alpha 与色差（⇒ ①②④），
    静态也对就量**该 part 的左右对称性与总像素数**（⇒ ⑥：整块或半边丢了），
    最后核 deformer 的 parent 链（⇒ ⑤）。跳过第一步会在静态数据上反复自我确认「差 0，没问题」，
    而用户看的是动态；跳过第三、四步会在**正确的位置上反复修一个根本不在那里的缺陷**。

23. **语义层名 ≠ 几何分组：同一件衣服会被劈进两个物理组，动起来就分层。**
    绑定器按层名挂物理（`bottomwear`→`def_Skirt`、`topwear`→`def_Body`），但 See-through 的数字
    只看颜色纹理、不知道「这块布属于同一条裙子」。实测 c05 裙子区 `y>820`：
    `topwear` **20,163px** / `bottomwear` **20,168px**，几乎五五开 ⇒ 一半跟身体（不摆）、
    一半跟裙子（摆），用户描述成「裙子分层了有一个固定不动的图层」。
    **修法**：把非裙子层在裙摆几何范围内的内容**并回 `bottomwear`**（实测 39,481px），
    让它整块跟 `def_Skirt`。判据要有几何范围（腿 bbox 上缘 / `--skirt-zone y0`），纯颜色分不开——
    白女仆装上衣和裙摆都是白的。

    ⚠ **必须归并整个几何区域，只归并「两层重叠」的像素不够。** 曾把条件收紧成
    `topwear ∩ bottomwear`（本意是保护手），结果非重叠的残留留了下来：裙子区仍有
    `topwear` **20,543px**，它 order 更高、又不跟 warp 变形，把已经变形的 `bottomwear`
    整块盖住 ⇒ 内部花纹被拉伸、外轮廓逐行位移全是 0。排除不该动的部件要用
    **几何减法**（如 `_mv &= ~sleeve_band`），不要用「只处理重叠」这种隐式限制。

    ⚠ **极端情况无法用图层解决：一个图层物理上不能在腿前又在腿后。**
    真实穿着里**后裙摆**在腿后、**前裙摆**在腿前；See-through 只给一个 `bottomwear`（c07 实测
    291,960px、bbox 撑满 `x[297,975] y[416,1110]`），order 又高于腿 ⇒ 后裙摆盖住腿脚。
    这不是参数能调的，必须**劈成 `skirt_back`(order < legs) + `skirt_front`(order > legs) 两片**。
    自动劈分的依据只能是几何（腿 bbox 中线上下 + 裙摆轮廓），在「腿被裙摆盖住大半」的素材上
    不可靠（同铁律 21 坐姿拆腿失效的原因）。**遇到就明说不易解决、给人工劈开方案，不要硬拆。**

    **同源判据**：怀疑「某块布料被劈进两层」时，直接量**目标几何区内各层的像素数**，
    两个层接近对半就是这个问题；比看渲染图快得多。

25. **用 VLM 描述的位置当坐标去修图，是整条验收里最容易犯的错。**
    用户报「右边的手透明/看不到」时，VLM 会给出一个看起来很具体的框（例：`x690-745, y475-540`），
    照着修了三轮都不见效——**因为那块在原图上的主色是 `(96,72,96)` 深紫，是衣料和头发，根本没有手**。
    用户的「手」在原图里本来就被腰侧和袖套挡住、看不清（他看完原图也确认「原图确实没有手」）。

    **正确顺序**：
    ① 先把「原图 vs 渲染」**整图并排**给用户看，让他指位置（或给带 100px 网格的原图让他报坐标）
    ② 拿到坐标后，**先在原图上量那块的主色**，确认它到底是什么（肤色？衣料？头发？）
    ③ 确认是目标部件了，才去量层覆盖与色差

    ⚠ 反过来也成立：**VLM 说「手不在了」时，先算像素再信它。** 同一批播放帧，
    VLM 判「手完全消失」，实测手区浅色点只有 4.6% 变化、色差 1.3–1.7 —— 它在夸大。
    用户看到的是动态，但**判断之前必须有像素数**；两者矛盾时报数据，不要替他在两个结论里选一个。

    ⚠ **被否 ≥2 轮必须索取参考**（原图、坐标、或分层单图）。
    做法：把 `handwear` 层单独渲染出来（其余全隐藏）给用户看，一眼就能确认手在不在这个层里、在哪个位置。
    继续在错的位置上迭代，比停下来问一句代价大得多。

26. **`def_Head` 必须挂在 `def_Body` 下，且数组里要排在它后面。**
    两者都写 `parent=None` 时，身体 `translateX ±16` 而头一动不动 ⇒ 脖子与头直接错开，
    驱动后整片露白（实测 **42,000px**），在用户眼里就是「手/头发那边透明了」。
    引擎按数组顺序解析 parent，`def_Head` 写在 `def_Body` 前面时可能拿到 undefined，
    所以 `def_Body` 要排在前面。

    ⚠ 头转幅度直接决定「头发甩多远」：发长 496px 时转 11° 让发梢横移 `sin(11°)×496 ≈ 95px`，
    而头发后面是空 backdrop ⇒ 露出成片白块。11° 收 8° 后单转头露洞从 2 万降到 1.6 万。
    **头发是刚性跟随头的**（`parent=def_Head`），physics 只在其上叠加，
    所以相对旋转给大了等于把头转幅度翻倍 —— 前发 ±9→±5、后发 ±7→±4。

27. **「看不到手/某部件」先量 `handwear` 左右对称性，而不是看渲染图。**
    原图是双手叉腰这类对称姿势时，左右像素数应当接近。实测一张立绘：
    `handwear` 左半 26,007px / 右半 11,814px（比值 **0.45**）⇒ 右手被判给了衣服层。
    追下去发现去向：`bottomwear` 7,359px + **没有任何层 3,444px** + `handwear` 3,060px ——
    被劈成三块，其中一块直接丢了。

    修法 `postprocess.py --reclaim-hand x0,y0,x1,y1`：框内「原图浅色（袖套/皮肤）」
    从 bottomwear/topwear/legs/neck/face 挖掉，再把原图色写进 handwear。
    实测挖回 21,113px、补进 16,625px，左右比值 0.45 → **1.09**，合成差 1.70 → 1.68。
    **必须给框**：白袖套和白上衣在颜色上分不开。

24. **物理幅度 ≤ 遮挡余量。被遮 W 像素宽的部件，位移不能超过 W，否则必露洞。**
    单图分层**无法恢复被遮挡区域**（原图那里没有像素），所以任何「A 挡住 B」的部位，
    B 一旦摆出原位就会露出空洞。用户对这种现象的描述是「残缺 / 没补全 / 有腿的痕迹」。

    实测两例：
    · **尾巴** `def_Tail` rotate **±24°**、尾巴约 300px ⇒ 末端横移 `sin24°×300 ≈ 122px`，
      而 `tail` 的 order=2 在 `legs`(3/4) 后面 —— 一摆就露出被腿挡住的空白，用户判「尾巴那块
      还有明显的腿部痕迹」。收到 **±10°**（末端 ~52px）+ physics `scale 420→180` 后牵连降到 2,469px。
    · **长发** 盖住尾巴/身体时同一机制。`ParamHairFrontSway` 16→11、`ParamHairBackSway` 12→8，
      缓解「c06 尾巴被头发遮挡的部分没补全，活动以后残缺」。
    · **转头是同一机制的隐藏输入，别只盯 hair 的 sway 参数。** 头发 deformer 的 parent 是
      `def_Head`（刚性跟随），发梢位移 ≈ `sin(头转角) × 发长`：发长 496px 时转 11° 就是 **95px**，
      后面是空 backdrop ⇒ 成片露白；发丝细，露出来是一段段「虚线断口」，用户读成「透明」。
      而头发自己的 `±9` 是**叠加在头转之上**的，等于把幅度翻倍 ⇒ 头 ±8 + 发 ±4/±5 才收敛。
      调任何头发参数之前先算这个乘积。

    ⚠ **别把这类问题误判成「语义错分」**。c05 尾巴最初被当成「tail 层里混了腿的像素」，
    实测 `tail∩legs = 21,427px` 但那块原图 **R−B 均值 −26.5、92.7% 是冷色** ——
    是尾巴自己的蓝，不是皮肤；按「暖色皮肤」判据只该挖 1,437px。
    **判据：先量重叠区的颜色族，冷色就是本体、暖色才是错分。**

    **替代解法（幅度不够用时）**：①让 B 绑成 A 的子级跟随（视觉上「B 本来就在 A 后面」成立）
    ②人工补画遮挡区（成本高、效果参差）③出图时就让两者分开摆姿势，从源头避免遮挡。

    ⚠ **没拆的部件要给它一个独立 deformer，不能让它挂在 `def_Body` 上吃全身位移。**
    不拆腿时 `legs` 默认挂 `def_Body`（`translateX ±16`），而腿是画序很靠底的层、背后只有空 `backdrop`
    ⇒ 身体一动就露出 **52,621px** 背景。换成独立 `def_Legs`（`translateX ±4`）+ 单独 physics 后，
    同一次驱动的露洞量大幅下降，而身体其余部分照常动。
    入口 `scripts/split_part_deformer.py`：给任一 part 换一个自建 matrix deformer + 参数 + 物理。
    代价是该部件不再「跟着身体整体走」，幅度给小、相位与身体同源即可。

    **验收口径：「露洞」和「正常露背景」必须分开数。**
    `hole = (diff>12) & (驱动帧该处纯白) & (原图该处非白)` —— 只看前两条会把「头顶头发飘开露出背景」
    当成缺陷。两条实测：只推裙子参数露洞 1,475px（正常），身体+头推满 38,295px（头发转开，待权衡）。
    详见 `references/acceptance-rules.md` 第 44 条。

25. **布料 / 尾巴 / 长发要用 `warp` 网格变形，不是 `matrix` 刚体。这是「动起来假」的第一号原因。**
    iki 同时支持两种 deformer：`kind:"matrix"`（pivot + translate/rotate/scale，整体刚体）与
    `kind:"warp"`（控制点网格 + 逐点 keyform offsets，真弯曲）。

    **只写 matrix 的傀儡不是 Live2D，是会平移的贴图。** 裙子绕一个点转 = 木板在转；
    尾巴绕根转 = 棍子在甩，末端横移 `sin(角度)×长度`（±24°、300px ⇒ 122px），必然越出
    遮挡余量露洞（铁律 24）。warp 能做到「底部偏、顶部不动」：既是布料该有的形变，
    末端位移又完全可控，两个目标一起满足。

    六个必守点（每个都实测翻车过，完整配方见 `references/warp-deformers.md`）：
    · **rest grid 的 row 0 必须是最大 y**（+y 向上）。把上下界传反 ⇒ 校验直接报
      `grid.points must be a regular axis-aligned grid`。
    · **keyform 的 `value` 是参数的 own-range 值、不是归一化**。写死 −1/0/1 而参数声明
      `min:-8,max:8` ⇒ 参数只走 1/8 量程，位移肉眼为 0，会被误判成「warp 不生效」。
      从 `model.parameters` 读回 min/max 再写。
    · **grid 必须覆盖整个 part 的 bbox**。只盖下半段 ⇒ 上半段不参与变形、和下层叠成
      「一层动一层不动」（用户描述与铁律 23 完全同形，但根因不同：那条是像素被分进两层，
      这条是同一层只变形了一半）。「顶端不弯」靠 offsets 的曲线指数 `(r/rows)**2`，
      不靠缩小网格。
    · **网格密度决定「切割感」**。4×4 摊在 749px 宽的裙子上每格近 190px，线性插值在格边
      折出硬棱，用户会读成「有一道切割线 / 像拼上去的」。加密到 **10×10**（每格约 75px）
      弯曲才是连续弧线；加密后 offsets 长度变成 `(cols+1)*(rows+1)*2`，别沿用旧常数。
    · **弯曲只能作用在布料真实纵段，网格仍覆盖整个 part。** 层的 bbox 常远大于那块布：
      实测 `bottomwear` 跨 canvas y[24,719]，里面是「粉领结 + 腰饰（y 24–499）」和
      「粉裙本体（y 500–699）」。按全高算曲线 ⇒ 裙子只落在网格最下 28%，位移被压到
      3–4%，用户看到的仍是「整块平移」。入口 `add_warp.py --bend-zone y0,y1 --amp px`
      （摆幅经验值：裙子宽度的 8–12%）。⚠ **`l.bbox` 不可信**（实测报 `(0,0,1280,1280)`），
      必须从 alpha 像素算真实范围；并用「按 100px 分段数像素 + 看该段原图主色」确认哪段是布料。
    · **部署前先跑结构校验**：`node scripts/validate_iki.mjs model.iki`（本技能自带，零依赖，不需要 iki 仓库）
      —— 查网格非轴对齐、keyform 量程不足、引用悬空、order 重复、网格过粗；要连引擎行为一起验再用
      `parseIkiModel`（`references/warp-deformers.md`）。
      warp 格式错在播放器里**只表现为 `window.model` 为 undefined、画布空白**，
      没有可读错误 —— 极易误判成「引擎不支持 warp」而放弃整条路线。
      手改 iki 时另一类同症状的雷：**自己追加的 physics 写了 `"inputs": []`**，
      `parseIkiModel` 报 `physics[N].inputs must be a non-empty array`（还要给 `mass`/`stiffness`/`damping`）。
      两者分工是「结构错 → `scripts/validate_iki.mjs`（已覆盖 `inputs`/`mass`·`stiffness`·`damping`/`output`）；
      schema 与引擎行为 → 过真 `parseIkiModel`」。

    ⚠ **warp 生效却有「外轮廓纹丝不动」时，查上层残留，不是继续调网格。**
    实测内部饰带变形 26,000px、而裙摆逐行边缘位移全部 +0：`topwear` 在裙子区残留 20,543px、
    order 更高又不挂 warp，盖在已变形的 `bottomwear` 上。**只归并「两层重叠」部分不够**，
    非重叠残留照样盖住（见铁律 23 的修法补充）。

    ⚠ **归并时用来排除的几何 mask，必须按解剖锚点核过范围。** `_mv &= ~sleeve_band` 这种减法
    一旦带子给大，就会把本该处理的内容**保护起来**：实测袖带 y 上限写到 820、而手腕其实在
    `y≈589`，整段裙摆落在带内被排除 ⇒ `topwear` 在裙子区每 25px 行残留 6,000–7,600px，
    外轮廓照旧不动。**跑完必须回数目标区残留**（归并后该层在区域内应接近 0），
    非 0 就是排除 mask 吃掉了目标，不要往网格或 keyform 上继续找原因。

26. **变形层级必须成链：头挂身体，父必须写在子前面。漏一条就会出现「某个部位透明」的假象。**
    实测绑定器把 `def_Head` 和 `def_Body` 都留了 `parent: -`（各自独立）：身体 `ParamBodyAngleX`
    平移 ±16px 时头一动不动 ⇒ 脖子与头整体错开，驱动后露洞 **42,000px**，
    用户指着手说「右边的手透明了」，而手本身完全正常。

    三条守则：
    · **`def_Head.parent = "def_Body"`**。脸/五官/头饰/头发全挂在 `def_Head` 下，这条一错全错。
    · **数组顺序：父排在子前面**。引擎按 `deformers` 数组顺序解析，parent 写在后面可能拿到
      undefined —— 播放器只表现成画布空白或部位错位（`scripts/validate_iki.mjs` 会拦这条）。
    · **改完先验「体动头是否同动」**：`ParamBodyAngleX` 推到满量程，看头与脖子交界有没有
      逐行位移突变或露白。这比任何全图像素差都更快定位到层级问题。

    **报障顺序**：用户说「某处透明 / 断裂」时，先花十秒核 deformer 的 parent 链
    （`json.load` 后逐条打印 `id / kind / parent`），再动像素。像素侧修好了而层级还断着，
    驱动帧照样露白，会被判「没修好」。

## 新工程复用旧管线的脚本时，产物会落在**旧工程**的目录里

用户的硬规则是「每个对话 / 每个新任务开独立工程目录」，但管线脚本里带着上一工程的硬路径：

- `run_local.sh` 是 `cd <老工程>/see-through` + `--save_dir ../out/layerdiff_output` ——
  拆层 PSD **永远写回老工程**，跟你在哪个目录执行无关。
- `extract_birefnet.py --base <新工程>` 传了也只影响部分产物，1280 输入图仍落在**脚本所在工程**的 `input/`。

**做法**：跑完立刻按前缀把本批产物 `cp` 到新工程（`input/<前缀>_square1280.png`、
`out/layerdiff_output/<前缀>*/`），之后所有数字（`backdrop`、合成差、层像素统计）都在**新工程的副本**上算。
不要改共享脚本去重定向 —— 老工程的历史复现还依赖这些相对路径。

**判断后台任务有没有真在跑**：`run_local.sh` 常被 `| tail -40` 包住，管道缓冲让日志在进程结束前一直是空的，
`process_manage(action='log')` 返回 0 行 `status: running` **不代表失败**。看 GPU 更可靠：
`nvidia-smi` 的显存与利用率（拆层起来后 19–20GB / 100%）+ 产物目录的创建时间戳。

## 用户一定会问的三个入口

1. **撤销**：功能一直在 `store.undo/redo`，只是按钮初态灰、无快捷键。补 `Ctrl+Z` 时要
   `if (焦点在 input/textarea/contenteditable) return`，把撤销让给浏览器原生。
2. **导入**：原来只有「导入图层组」，且按**文件名**卡 role，乱命名 / jpg 全被拒。

   「整张作为一个部件，不会眨眼张嘴」。

## 验收：先让它在播放器里动起来

`cut → autoRig` 只代表文件写出来了，必须自己加载一次并逐项回读参数。

```js
await fetch('/model.iki').then(r=>r.text()).then(t=>window.iki.load(t))   // load 吃文本，不吃 URL
window.__h = setInterval(() => window.iki.set('ParamMouthOpenY', 0.9), 16)  // 待机会覆盖，要持续重设
window.iki.get('ParamMouthOpenY')                                          // 回读才算真设上
```

- **`canvas.width` 必须是模型画布尺寸**（不是 300×150）。后台标签页把 rAF 和 setInterval 一起节流，
  resize 根本没跑，截到的是 300×150 放大图，1px 的层缝会被看成 4px。先 `Page.bringToFront`
  + `Emulation.setFocusEmulationEnabled` + `Emulation.setDeviceMetricsOverride`。
- `capture_screenshot()` 每次返回**同一路径**，连拍会互相覆盖 → 拍完立刻改名。
- **隐藏页面 UI 只按 id 藏**（`#bgsw` / `#tip` 这类）。`querySelectorAll('div,p,span,button')` 会把 canvas
  的父容器一起藏掉，截图报 `Cannot take screenshot with 0 width` —— 看着像模型崩了，其实是自己把画布藏了。
- 判「某部件动没动」用**分区运动量**，不要看缩略拼图：
  `python scripts/measure_motion.py <帧目录> --heat heat.png --gif out.gif`。
- 判「有没有露底层」用**肤色像素数**，摆动帧不得高于静止帧：
  `python scripts/measure_underlayer_leak.py <帧目录>`。
- 判「旋转/摆头是否生效」用上半张像素差（均值差 <2 才是真没动），不要问 VLM。

## 多模型并排展示页（用户说「都做成 live2d，网页展示出来我看看」）

交付形态：`examples/player/gallery.html` + `src/gallery.ts`，2×2 网格，每格一个独立
`IkiPlayer` + `IkiMotion`，各模型的 `.iki` 放 `public/`。

- 每个 canvas 设成**模型自己的画布尺寸**（`canvas.width = model.canvas.width`），CSS 那条
  `width:100%` 负责自适应；两件事别混。
- **物理没有主动力**，必须每帧写 `ParamAngleX/Y/Z` + `ParamBodyAngleX/Z`，否则尾巴 / 头发 /
  耳朵 / 裙全部停在 0。四个轴**错开周期**（5.0 / 7.5 / 4.0 / 6.5 / 8.0 秒）才像自然待机，
  同周期会摆成机械钟摆。
- 一个 RAF 循环里遍历全部实例写参数 + `motion.update(now)`；**不要每实例各起一个循环**。
- 页面暴露 `window.ready` / `window.insts` 供自动化断言；加载完逐卡读 `window.model.name` 核对，
  防某张 iki 复用了同名文件（见铁律 15）。
- **交付前用两帧差分证明真的在动**：间隔 800ms 抓两帧，`(abs(a-b).max(2)>8).sum()` 应达十万级。
  实测四模型共 **408,297px**，单卡 75k–140k（坐姿大尾巴的 c10 最大）；这个数字比截图更能
  说明「不是静态贴图」。
- 四张图各自的前置条件不同（拆腿 / 无 legs 层 / 坐姿未拆腿），卡片文案里直接写明，
  用户一眼就知道为什么这张腿不独立动。

## 交付口径

- 交付物按**标准命名 PSD** 设计，让美工能参与；别把「先转成自家格式」当默认步骤。
- 交模型必须同时给：`.iki` 路径、层目录、四格效果图、**能动的参数清单**、以及下面的固有限制。
- **跨工程 / 跨会话指认一个模型时给四件套**：工程内代号（`c04` / `c15` / `c07` 这种）+ `.iki` 里的
  `name` 字段 + 绝对路径 + 规格（画布 / parts / deformers / physics）。同一个工程里常并存三四个模型，
  只给「之前那个 Q 版」会指错。同时**点明哪个是唯一可直接交付的成品、哪些只是流程验证件**。
- **已经交付过的成品文件（GIF / 图 / 模型）原样复用，不要为了「压缩一下」重制。**
  缩尺寸、减帧、改帧时长之后它就不是他手上那个文件了，会再被要求换回原版。
  要放进仓库或文档当预览，直接拷原件；确实必须缩就先问。
- **默认表演照原图叙事**，不能套通用笑脸：先写「她正在干什么 + 什么情绪」，再翻成参数。
- **测运动的帧不是交付动画**。量完立刻撤驱动、姿态归零，另拍一遍纯 idle 作为交付片。
- **调参工具不是播放器**。交付要另起一个「打开就在播」的页面（GIF 或本地 http 服务），
  并用一张表说清每个端口是什么。
- 逐部位迭代时**一轮只动他点名的那一处**，并主动交代这一改的代价。
- **不要拿静态像素差当「修好了」的证据****。** 静态渲染可以与原图逐像素差 0，而动态仍分层、露洞、
  跟错层摆——用户看到的永远是动态。汇报时必须给**驱动后的两帧差**（参数推到满量程）
  以及「外轮廓到底动没动」，只给「平均差 2.54」会被当场驳「根本就没修好」。
  实测教训：四张模型连续多轮拿静态差报告进展，用户最终回一句「4 个都没能修复，问题很严重的那种」。
- 卡在视觉判断上时，出「同框同倍」的成对局部图 + 编号问题让用户肉眼判，不要反复猜。
- **同一处被用户否 ≥2 轮就停止猜坐标，改交两样东西让他指认**：①带 100px 坐标网格的原图
  ②把可疑层单独渲染出来（其余层全隐藏）。当他说「看不到手」而你的数据说手色差 2.4、合成差 1.68 时，
  分歧只可能来自「你们说的不是同一处」；再修一轮只会把本来对的地方弄坏。
  给图时同时列出「我查到的事实」（层内像素数 / 色差 / 分布），再请一句坐标或左右方向，
  比继续猜快得多 —— 这不是把判断丢回给他，而是先把测量口径对齐。
- **回归比缺功能严重**：改编辑器只做加法，不碰既有导入/绑定路径。
- **对外说明（README / 发布页）的能力声明后面必须跟实例表**：输入条件 / 产出规模 / 可量化指标 /
  耗时 / 人工改动量。三行真数字比三段原理有说服力，只写「支持 X」等于没说。
  具体排版与发布前卫生检查见 `github-repo-management`。
- **发布成「别人能装」的技能时，光有源码仓库不算交付。** 用户会明确要求一整套，缺一项都要补：
  ① **打 tag + 建 release**（首页右侧 Releases 区不能是灰的，源码 zip 由 GitHub 自动生成）
  ② **技能目录单独打一个 zip 挂到 release 附件** —— 别人解压即用，不必 clone 整仓
  ③ **一份使用手册**，三块缺一不可：**全流程需求**（硬件 / 依赖 / 素材要求表——写清什么素材会返工）、
     **Agent 操作手册**（装技能步骤 + 接到任务后的执行顺序，每步带可验证判据）、
     **「用户描述 → 技术根因」对照表**（他报症状时直接查表定位，不要每次重新推理）
  ④ **一段可直接复制给 Agent 的自动安装提示词**：clone → 拷技能目录 → `skill_view` 回读校验 →
     报告版本号/篇数/个数，并明写「不要跑生成，只装技能」。
  缺 ④ 时用户会问「如何使用」却仍要自己翻文档；他要的是把那段话贴给另一个 Agent 就装好。
  该说的边界同时写进 release 正文：三条方法学限制（被遮挡不可恢复 / 单图层裙摆劈不开 /
  坐姿腿不能拆）要摆在明面上，别只写在 docs 里等人挖。
- **技能目录和发布仓库是同一批脚本的两份拷贝，改完必须机械核过，不能只说「已经拷过去了」。**
  迭代管线时只改本机技能、仓库停在旧版是这条线最容易发生的漂移：实测仓库 `skill/` 还停在
  v2.0.0、`pipeline/postprocess.py` 只有 231 行（本机 537 行）、新写的 `add_warp.py` 整个缺失。
  三个检查代替印象：①两边 frontmatter 的 `version:` 一致 ②关键脚本 `grep -c ""` 行数一致
  ③`git status` 里应列出**全部**新生脚本与新增 references。push 之后再用 GitHub API 读一次
  `contents/pipeline`，确认新文件在远端真有（文件名 + 字节数），本地 commit 成功不等于远端到位。

## 固有上限（要主动说，不是 bug）

| 限制 | 说明 |
|---|---|
| 补画是部分的 | 背遮区域实测只补 36–54% |
| 没有 lip set | 张嘴 = 把嘴线纵向拉大，开度 0.9 有锯齿感 |
| Q 版转头幅度小 | 头大脖短，±30° 像素差只有 ~10，肉眼仍是正面 |
| 单图切层层缝 | 每层硬切互不重叠，靠补边压到 0.0x%，压不到 0 |
| 缺内容补不了 | 口腔、侧脸内耳、被完全遮住的皮肤；**被遮挡部位移位必露洞，只能用「幅度 ≤ 遮挡余量」换** |

## templates / scripts

- `templates/landmarks-min.json` — cut 管线的最小 landmark 骨架
- `scripts/probe_landmarks.py` — 像素游程扫描定眼框/虹膜（别让 VLM 打坐标）
- `scripts/apose_check.py` — 三段 75% 判 A-pose（只对骨架图标定）
- `scripts/bg_whiten.py` — 背景 flood-fill 归纯白 + 四角验收
- `scripts/extract_birefnet.py` — 通用抠图一条命令：
  `python extract_birefnet.py <原图> <前缀> [--base 工程目录] [--tip-box x0,y0,x1,y1]`
  → 软 mask / 二值 mask / 1280 白底输入图 / 涂色核对图四件（选型与坑见 `references/matting.md`）
- `scripts/zoom_face.py` — 头区/嘴部放大拼条
- `scripts/measure_motion.py` / `measure_underlayer_leak.py` / `measure_gaps.py` /
  `diff_against_original.py` — 运动量 / 露底 / 层缝 / 差异统计
- `scripts/validate_iki.mjs` — **零依赖 `.iki` 结构校验**，部署前必跑：
  `node validate_iki.mjs out/model.iki`。退出码 0/1 可接进脚本。专门覆盖「在播放器里只表现成画布空白、
  没有任何可读错误」的那批格式错：warp 网格非轴对齐（row 0 不是最大 y）、
  keyform 只覆盖部分量程（写 −1/0/1 而参数是 −8..8 ⇒ 只走 1/8，位移肉眼为 0）、
  part 挂 warp 却没有 mesh、引用悬空、网格 ≤4×4 的「切割感」预警，
  另外拦「parent 排在子后面」（引擎按数组顺序解析会拿到 undefined）与 physics schema
  （`inputs` 空数组 / 缺 `mass`·`stiffness`·`damping` / `output` 参数不存在）。
  它只证明结构自洽，发布前仍要过真 `parseIkiModel`。
- `scripts/split_part_deformer.py` — 给单个 part 换独立 matrix deformer，把它的位移幅度收到
  遮挡余量以内（不拆腿时压 `legs` 的露洞）。同时把「物理块必须满足什么」示范成一个可抄的模板。
