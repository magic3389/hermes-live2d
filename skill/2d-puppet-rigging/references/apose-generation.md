# 生成 A-pose 立绘（绑定素材）

目标：正面全身、手臂斜下张开、纯白背景、Q 版比例的立绘，用作绑定 / 切层的基准素材。
配套脚本：`scripts/apose_check.py`（几何验收 + 批量筛查）、`scripts/bg_whiten.py`（背景归纯白）。

## 一句话结论

**有参考原图就走 Qwen-Image-2.1 的参考编辑；没有原图才退回 SDXL + 骨架。**
原因只有一条：体型。骨架路线上体型无论怎么调都不对，而参考编辑根本不需要体型词。

| 路线 | 姿势来源 | 体型来源 | 结果 |
|---|---|---|---|
| **A · Qwen-Image-2.1 参考编辑**（首选） | 指令（中文分条） | **直接继承参考图** | 一次成功，纤细 2.5 头身 + A-pose + 纯白底 |
| B · SDXL + OpenPose 骨架（备选） | 骨架 | 提示词（无解） | 不加体型词→细长腿；加 `chubby`→**肥胖侏儒** |

B 路线两种失败都被用户当场退回（"个个画成了肥胖侏儒"）。**不要在这条路线上继续调参换词**，直接换 A。

# 路线 A · Qwen-Image-2.1 参考原图 + 指令编辑（首选）

## 模型（本机已备齐）

`Documents/comfyui files/models/` 下：

| 用途 | 文件 | 大小 |
|---|---|---|
| 主干 | `qwen-image-2.1-UC-Q8_0.gguf` | 7.6GB |
| 文本编码器 | `qwen3vl_8b_int8_convrot.safetensors` | 9.35GB |
| VAE | `qwen_image_2.1_vae_bf16.safetensors` | 644MB |

节点链（API 格式，可直接提交）：

```
UnetLoaderGGUF(qwen-image-2.1-UC-Q8_0.gguf)
CLIPLoader(qwen3vl_8b_int8_convrot.safetensors, type="qwen_image", device="default")
VAELoader(qwen_image_2.1_vae_bf16.safetensors)
LoadImage(<参考原图，必须先在 <ComfyUI>/input/>)
TextEncodeQwenImage21(clip, prompt, negative_prompt="", resolution=1024, vae, images.image_1=[LoadImage,0])
EmptyLatentImage(w,h)  →  KSampler(euler / simple / 30 步 / cfg=1 / denoise=1)
VAEDecode → SaveImage
```

三个接线硬点（每一个都报过错或出过错图）：

1. **参考图的输入名是 `images.image_1`**（自动增长输入），不是 `image`。写成 `image` 直接 400。
2. **`KSampler.latent_image` 接 `EmptyLatentImage`，不要接 `TextEncodeQwenImage21` 的第三个输出 `latent`**
   —— 那个 latent 由节点的 `resolution` 决定，**是方图**，会把竖版立绘压扁成 1024×1024。
   编码节点只供 `positive`/`negative`（`["5",0]` / `["5",1]`）。
3. `QwenImage21Cache.device` 合法值只有 `auto/gpu/cpu/off`；`dtype` 才能填 `default`，两个别混着抄。

## 指令怎么写（这是成败关键，不是参数）

中文直接可用（Qwen3VL 编码器原生中文）。分条列，**七段缺一不可**：

```
1) 姿势：正面站立，双臂自然垂在身体两侧并向外张开约 30 度，手臂与躯干之间必须留出可见的空隙
   （能透出背景），双手手掌张开、五指自然分开、掌心朝内，手大约在髋部高度；双脚并拢站直。
2) 去掉她手里的 <原图道具>，双手空着。
3) 背景改成纯白色 #FFFFFF，不要任何阴影、地面、渐变或装饰。
4) 角色的一切外观必须原样保留：<逐条点名发型/呆毛/兽耳/尾巴/服装/配饰/鞋/眼睛/>。
5) 头身比例保持不变，仍然是 Q 版 2.5 头身，**不要把她画胖、不要压扁、不要变成矮胖侏儒**，
   四肢保持原图的纤细短小比例。
6) 画风保持原来的赛璐璐平涂、深<色>粗描边。
7) **表情必须换掉**：嘴巴只画成一条浅浅上扬的弧线、双唇闭合；不要张嘴、不要露牙齿、
   不要露口腔、不要咀嚼动作、不要含着食物、不要做吃东西的表情、不要流口水、不要嘴角沾米粒。
   眼睛平静看着镜头，不要惊讶瞪大、不要紧张汗滴。
```

- **第 5 条是用户否掉整组的原因，必须写死。** 不写这句，模型会往「可爱胖娃娃」方向偏。
- 第 2 条不能省：原图里的碗、筷子、道具不会自己消失，不点掉就会被塞进 A-pose 的手里。
- 第 4 条要**逐项点名**，写「保持一切特征」等于没写。
- **第 7 条同样不能省，漏掉会整批报废。** 参考图的表情会和道具一起被搬过来：原图是「偷吃被抓包、嘴里还在嚼」，
  生成的 A-pose 就仍是一张咀嚼嘴（有的张还带嘴角米粒）。姿势、道具、背景、体型全对，用户仍会整批退回
  （「其他的嘴错误，保持了吃大米饭的姿势」）。
  ⇒ 凡是参考图带**动作性表情**（吃 / 哭 / 困 / 惊讶），都必须显式写出目标表情并逐项否定原表情；
  `cfg=1` 下负面提示不生效，这些「不要…」只能写进正向。

## 定向二改：用户说「按第 N 张加 X、去掉 Y」

别从原图重生成 —— 把**已交付的那张**当新参考图，只改点名的那几处，一次就成，姿势 / 体型 / 画风零漂移。

指令固定三段：

1. 逐条「修改 1 / 修改 2」，每条都写「要什么」+「不要什么」（`不要黑色袜子、不要连裤袜、不要短袜`）。
   只写要什么，模型会给一半。
2. 一段「必须原样保持」：姿势、头身比、表情、背景、服装清单、发饰、尾巴、画风逐项点名。
3. 细节要落到可判定的量：`袜口位于膝盖上方约三指处、带一圈白色蕾丝边`。

去装饰时要点名保护同色的东西：`去掉头侧的蓝色水滴装饰` 必须补 `围裙上小鲸鱼喷出的水花要保留`，
否则模型会把同色小装饰一起擦掉。改完仍然暗示「这是一张全身立绘」，否则加袜子的指令会把镜头拉到腿上。

## 实测参数与耗时

896×1152 / 30 步 / euler / simple / cfg=1 / denoise=1 → **109 秒/张**（3080 20GB，含首张权重加载）。
比 SDXL 慢一倍多，但**一次就对**，总耗时反而低得多（SDXL 路线 50 张才挑出 10 张能有用的）。

`cfg=1` ⇒ `negative_prompt` 数学上不生效，要禁止什么一律写进正向（明写「不要…」）。

**改提示词后先跑 2 张验生效，再批量。** 一次 48 秒，两张不到两分钟；直接开 12 张的话，
万一某一节没写进去就是白跑十分钟还要重新排队。验完看的是新加那一节的效果（例：嘴是否真闭合）。

### 改生成脚本：用 patch 工具，不要用 bash heredoc

`qwen_apose.py` 这类脚本的提示词是**多行字符串拼接**。用 `python - <<'PY'` 里的 `s.replace(..., "…\n")`
去改它，`\n` 会被 shell 当成真换行写进源码 → 字符串字面量断行 → `SyntaxError: unterminated string literal`，
整批一张不跑。正解：`patch` 工具直接对文件做替换（new_string 里写 `\n` 是字面量，不经 shell），
改完先 `python -c "import ast; ast.parse(open(f).read())"` 过一遍语法再启动批量。

## 验收

1. 原图四角实测 245–252（接近白但非纯白）→ 仍需 `scripts/bg_whiten.py` 压一遍；
   Qwen 的底比 SDXL 的白很多，`thr=180 / sat=60` 一次就够，不必逐档试。
2. 角色 bbox 四边留白 > 8px。
3. **表情/嘴型单独放大看，而且必须逐张看。** 嘴只占整图千分之几，缩略图里看不出来，批量交付前会漏，
   用户一眼就抓到。裁「角色 bbox 顶端往下 42% 的头区」再取下半截放大到 520 宽：
   `python scripts/zoom_face.py out/g01.png out/g04.png out/g09.png --mode mouth`（`--mode face` 看整头）。
   判定口径：闭合弧线=合格；能看到口腔内部的暗色=张嘴，退回。
4. **画质与体型判定交给用户**：把成图和参考原图并排发，问「体型对不对、有没有变胖」。
   VLM 会答「纤细 2.5 头身」，但这正是被用户否过的那一版也能通过的题 —— 只当线索。

# 路线 B · SDXL + OpenPose 骨架（没有参考原图时）

## 姿势必须用骨架

提示词写 A-pose 实测两轮全失败（SDXL / WAI-Illustrious / chibi 2.5 头身）：

| 写法 | 实际得到 |
|---|---|
| `a-pose, arms down and away from the body at 45 degrees, hands open` | 双手在胸前交握（祈祷状） |
| 加权重 `(a-pose:1.6)` + 负提示 `hands clasped, praying hands, interlocked fingers` | 双臂向上外展成 Y/V 形，手到头部高度 |

chibi 模型的提示词空间里「45 degrees」会被解成任意方向，而叉腰 / 交握 / 手收身前是极强的可爱姿势先验。
**标准姿势一律用 ControlNet 骨架，不要靠文字。**

## 骨架与强度

COCO-18 关键点 + OpenPose 官方 18 色 + Q 版比例（大头短身）。832×1216 画布下可用取值：

```
nose(416,330) neck(416,452) 肩(320/512,472) 肘(250/582,592) 腕(192/640,702)
髋(372/460,782) 膝(366/466,992) 踝(360/472,1158)
```

→ 上臂外展 30.3°、前臂 27.8°，手落在髋上方。手到髋部高度才是 A-pose；手到肩高就成 T-pose。

Union ControlNet 三个必须：

1. `ControlNetLoader` 装 `controlnet-union-sdxl-1.0-promax.safetensors`
2. **必须接 `SetUnionControlNetType`，`type='openpose'`**，否则按默认类型乱解
3. `ControlNetApplyAdvanced` 的输出同时接 KSampler 的 positive 与 negative（outputs[0]/[1]）

强度甜点：**strength 1.40 / start 0.0 / end 0.95**

| strength / end | 结果 |
|---|---|
| 0.85 / 0.85 | 画面正常，姿势跑偏成叉腰 |
| 1.30 / 1.00 | 仍是叉腰，还多出头顶「提线」 |
| 2.00 / 1.00 | 姿势完全正确，但人物被画成骨架线框 |
| 1.15 / 0.70 | 姿势对；提示词一写生动姿势就掉（12 张只 4 张） |
| 1.15 / 0.85 | 姿势对 + 画面不降质（13 张出 6 张） |
| **1.40 / 0.95** | **姿势最稳（12 张出 6 张），画面仍完整** |

骨架线条常被理解成提线木偶的绳子 → 负提示封：`puppet strings, marionette, strings attached, wires`。

## 体型：这条路走不通，只能止损

OpenPose 只有关节点、**没有体块宽度**。模型照细骨架画，Q 版角色必然被拉成细长腿（12 张里 7 张判「过瘦」）。
补 `chubby plump body, short thick legs, wide hips` 能治瘦，但**矫枉过正成矮胖侏儒**，同样被退回。

可用区间极窄，实测只在「chubby + 1.40/0.95」时接近正常。**不要指望靠这套词稳定出货**：
到这里就该停手，反问用户「有没有原图可以给我参考」——有原图直接换路线 A。

## 提示词：三处别自己「优化」

| 不要加 | 代价 |
|---|---|
| `(FFFFFF pure white:1.3)` | 整张画面被冲淡：发色从深蓝变冰白，黑白对比塌掉，看起来「灰」 |
| `character reference sheet, model sheet, neutral standing pose` | 变成僵硬设定图：细节简化、表情呆板、构图单调 |
| 负面提示从 60 余 token 膨胀到 160+（连 `dynamic pose, action pose` 一起禁） | 画面失去生命力 |

正确做法：神态写活（`bright sparkling eyes, soft gentle smile`），负面提示保持精简（<100 token）。

### 用户已认可过一版时：逐字复制，不要优化

用户说「还不如上一轮 / 按照最开始那版的提示词来做」，要的是把那一版原样搬过来，**只改动作段**：
身份段整段复制（包括看似与需求矛盾的同款背景词）、负面提示原样、原版的情绪词保留。

改稿前先做差异对比（抽出两版 IDENTITY / NEGATIVE 的分词数与关键词是否出现），把差异表列给用户看；
差异里只要出现自己新加的东西，先删了再跑。**先 diff 再调参** —— 直接拧 strength / end / 步数是多轮无效迭代的典型原因。

# 两条路线共用：背景归纯白

### 坑 A：规范自带的暖米底与「纯白背景」直接打架

角色规范身份段末尾常是 `warm ivory-beige background`。照抄它又要纯白底，模型画成**深卡其**
（实测四角 `(196,170,126)`，饱和差 69–85）。这种底色压不白：阈值放到 min≥160 / sat≤80 仍会啃掉肤色与金饰。

→ 只把这一句换成 `pure white background, simple white backdrop`，其余照抄。实测四角合格率从 0/12 变 12/12。

### 坑 B：模型的 "pure white" 都不是 255

SDXL 出冷白偏蓝 `(233,242,252)`；Qwen 出近白 `(245,252,253)`。按 `>=250` 判定命中率只有 0.2–4%。

→ 后处理归白（`scripts/bg_whiten.py`）：判据 `min(rgb) >= thr and (max-min) <= sat`，
再从画布四边 flood fill，**只把与边缘连通的背景**设成 255。角色内部的白围裙 / 白袜被深色描边包住，不会被波及。

| 背景实际色 | thr / sat |
|---|---|
| 冷白偏蓝 (231–237, 240–252) | **215 / 40** |
| 近白 (245–252) | **180 / 60** |
| 暖米 (237,212,188)、(243,218,189) | **180 / 60** |
| 更暗的暖米 (229,204,178) | **175 / 65** |

压完必须验**角色轮廓外 3px 环**是否 `(255,255,255)` 且 `R−B = 0`（米色残留会表现成暖晕）——只验四角不够。

# 验收：几何判定只对骨架图有效

VLM 看拼图小图会给出自相矛盾的结论（同一张图两次判「叉腰 / 不是叉腰」）。
`scripts/apose_check.py` 数每条横行的角色连通段：A-pose 时手臂与躯干间有背景贯通 → 该行 3 段；
叉腰 / 手收身前 → 1 段。实测标定（**样本全部来自 SDXL 骨架图**）：

| 人工确认样本 | 三段占比 | 单段占比 |
|---|---|---|
| 真 A-pose | 82–93% | 1–13% |
| 叉腰 / 手在前 | 35–67% | 18–36% |

→ **阈值 75%** 能把那两批完全分开。

🔴 **但它对 Qwen 参考编辑出的图会误判**：Qwen 画的手臂更贴近身体，空隙只有几像素到 20px，
三段占比掉到 1–60%，被判 NOT-A-POSE，而视觉上确实是 A-pose（VLM 同张判「是 A-pose」）。
⇒ **Qwen 图不要用三段阈值当否决条件**，改看「左右两侧是否各有一个独立的小段（手）」或直接请用户目检。
把这条判据当「骨架图的筛查器」，不是「A-pose 的普适定义」。

四条硬指标，逐张过（骨架路线）：
1. 四角 40×40 区域 `min(rgb) == 255`（要最小值，不是均值）
2. 角色 bbox 四边留白 **> 8px**（贴边是生成问题，压白救不回来）
3. 纯白占比 50–80%（过高说明角色太小或被吃掉）
4. 三段占比 ≥75%

批量：`python scripts/apose_check.py --batch "<ComfyUI>/output/<prefix>_*.png"`

# 「一组 N 张」≠ N 次独立采样

**这是本类任务最容易交付失败的地方。** N 次独立生成出来的是 **N 个不同的角色**：服装层数、发型轮廓、
体型宽窄、配件有无都在漂。单张都能看，整组放在一起会被判「规格不统一，不能交」。

开工前先问清用户要哪种：

| 用户要 | 做法 |
|---|---|
| N 个候选，自己挑一张 | N 次独立采样 + 几何/白底/画质三重筛，**留一个 15–20 张的备选池并编号** |
| 一组风格完全一致的图 | 先出 1 张最合格的做源，再 img2img 衍生：denoise 0.45–0.55 + 骨架 1.10 / end 0.60 |

img2img 衍生的两个必然结果：① 变体继承源图的**背景色**，源图不白则变体也白不了；
② 变体之间相似度高，想拉开差别只能靠换服装 / 表情 / 配件的提示词，不能靠改 denoise。

备选池的好处：用户说「第 5 张不行」时直接换池子里的编号，不必重跑。索引图按「三段占比 + 最小留白」标注。

# 合格率预算

| 路线 | 可用率 | 10 张要跑多少 |
|---|---|---|
| Qwen 参考编辑 | 高（第一版即命中全部硬指标，主要风险是体型措辞） | 10–12 张 |
| SDXL 骨架（姿势+体型圆+画质够） | **20–40%** | 30–40 张 |

SDXL 路线丢掉的原因分布：姿势跑偏 ~35%、体型过瘦 ~30%、崩坏 ~20%、背景不白 ~15%。
逐张视觉核对，不要靠参数假设；连续两批不合格就换路线，别在词和参数上刷第 N 轮。
