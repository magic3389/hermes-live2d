# 切层与对比：合法依据、逐层实测、配方

SKILL.md 第 8 条（连通域）、第 12 条（keep_as_is）、第 13 条（1:1 diff）、第 14–17 条（颜色拆分/统计陷阱/原图对照）的展开。

## 1. 每层到底能不能拆（实测连通域）

对 See-through 出的 17 层 PSD 逐层跑 `ndimage.label(alpha>30)`：

| 层 | 连通域 | 能否细分 | 依据 |
|---|---|---|---|
| `legwear` | **1**（43389px, x[578,763]） | **不能** | 大腿根到脚踝连成一块，素材里没有左右两条腿 |
| `footwear` | 2（中间 7px 天然空隙 631-638） | 能 | 空隙是素材本来有的 |
| `ears` | 2 主块 + 各 2–3 个小件（蝴蝶结） | 能 | 按质心 x 把**所有**连通域归到左右两组；只取最大两块会丢蝴蝶结 |
| `front hair` | 1（63347px） | **不能** | 拆侧发露额头底层；拆呆毛露黑色背景（见 §2） |
| `back hair` | 1（178043px） | **不能** | 拆段必露后发底层 |
| `tail` | 1 | **不能** | 拆段必露缝；整块绕尾根转，尾尖摆幅天然最大 |
| `topwear` | 1 | 按颜色 | 白色围裙 72.6% vs 深蓝上衣 |
| `handwear` | 1 | 能不拆就不拆 | 深蓝袖 67%（29147px）vs 肤色手 8%（3414px）；颜色拆分留拼缝（见 §4） |

**判定顺序**：先数连通域 → ≥2 就直接按连通域分；=1 再看有没有颜色/语义分界 → 都没有就是不能切。

**单连通域又必须独立动画时**：先在素材上补画（inpaint 出真实的空隙/边界），让它变成 2 个连通域，
再按连通域分离。**这一步是画图不是绑定**，要先跟用户确认，交付时明说这是补画而不是切原图。

**为什么补阴影再切也不行**：补一道接触阴影再沿阴影切，切口仍是我画的直线/曲线，
只会把「一条粗腿」变成「两半各少一块、中间一条暗线」，用户一眼判成几何切。

**为什么重叠也不救**：呆毛曾按 y<160 / y>=130 切、重叠 4156px，静止看不出；一转重叠跟着转走，
前发顶边（y=130 处只有 52px 宽）让开就是黑背景。重叠是双重绘制，不是补画。

## 2. under-paint：给会被转开的部件补底

耳朵从 `headwear` 抠走后，headwear 上留两个耳朵形状的洞；耳朵一转洞就露出来 ——
用户判「耳朵位置有个固定（原图位置）的耳朵边缘痕迹留存」。

**两个必踩的错**：

1. **用颜色阈值圈范围会漏掉浅色边缘。** 「蓝>70 且 蓝>红+20」只圈到深蓝主体，
   耳缘那圈**浅色绒毛边**仍留在 headwear 里 → 转开就是一道浅灰白的耳形细边（就是「残影」）。
   正解：以深蓝为种子做**连通域**，取与之连通的全部 headwear 像素，再外扩 3px 吃抗锯齿边。
   实测从 20553px 扩到 38666px，耳区差异 10926→9846px。
2. **纯色填充会留下可见补丁。** 填 rgb(64,102,171) 出来的是一块没有纹理的蓝板，转开一眼可辨。
   正解：**从相邻同材质层拷像素** —— 按 `back hair` → `front hair` 顺序找同位置 alpha>200 的源，
   `filled[earm] = src[earm]`；源也透明的位置**保持透明**（那里本来就是背景，不该填色）。

`headwear ∩ ears` 有重叠（实测 18399px）**是 under-paint 的定义，不要当 bug 修掉**。

## 3. 摆动幅度：肉眼可辨的最低值

`实际角度 = (参数摆幅 / 参数半量程) × binding 角度`

| 部件 | 参数摆幅 | binding | 实际角度 | 判读 |
|---|---|---|---|---|
| 呆毛 | ±4.5 | 20° | ±3.6° | 看不出（质心只漂 4.4px） |
| 呆毛 | ±19.8 | 26° | ±16° | 可辨且不夸张 |
| 耳朵 | ±1.4 | 14° | ±1.4° | 完全看不出 |
| 耳朵 | ±7.2 | 20° | ±7.2° | 轻微抖动，合适 |
| 裙 | ±4.0 | 8° | ±1.3° | 可辨 |

目标带：呆毛 15–20°、耳朵 7–10°、裙 1–3°。小于这个带时「数据上有变化、肉眼判没动」，
别拿运动量数字跟用户争。

**钩形呆毛绕根转，视觉上是「弧度高低」而不是左右甩** —— 形状决定的，不要靠继续加大角度去追「左右摆」。

**枢轴放哪决定「灵动」还是「漂浮」**：耳朵枢轴放在耳朵**外端**时，整只耳绕自己的外侧转，
视觉是飘在头外的浮空件；挪到**贴头的内端**（实测 x 430 → 622）才像长在头上、绕耳根抖。

## 4. 一件衣服被切成两层（This asset 特有）

| 位置 | 落在哪两层 | 后果 |
|---|---|---|
| 围裙 | 上胸在 `topwear`（白 72.6%）、裙面在 `bottomwear` | 一个摆一个不动 |
| 袖子 | 与手同在 `handwear`（蓝 67%） | 两条胳膊全压在围裙前面 |

**围裙**：按颜色拆出 `apron_top`，与 `bottomwear` 挂同一个 deformer（同枢轴）—— 这一拆是安全的，
两侧 mask 严格互补、白围裙没有邻接的同材质件。

**袖子：不要拆。** 按蓝色拆成 `sleeve`/`handwear` 会因形态学改动边界而在手臂上留**拼缝**
（用户判「左右胳膊有了拼缝」）。实测 `围裙∩手` 只有 268px、`围裙∩袖` 3698px ——
整块 `handwear` 前移到围裙之前即可：袖子被围裙盖住，手在围裙外照样露出，结构上不可能有缝。

正确 draw order 片段：`legwear → footwear → neck → bottomwear → handwear → apron_top → topwear`
（鞋在袜之后 = 鞋压袜；handwear 在围裙之前 = 袖子被盖、手在外；topwear 最上 = 深蓝上衣）。
⚠️ 其中「鞋压袜」这一条是**量出来的**（区差异 1916 vs 3634px），不是从原图观感推的 —— 详见 §6。

## 5. 三色对比怎么读

`scripts/diff_against_original.py` 出三色图：

- **红** = 共同区差异 >25：层级/位置/遮挡不对
- **蓝** = 原图有、模型没有：丢件或被上层盖住
- **黄** = 模型有、原图没有：多件、错位、边缘膨胀

读法：
- 黄集中在「服饰装饰/花边/领口/袜口」这类交界处 → 多半是层与层重叠处的 alpha 叠加，不是整身错位
- 黄沿整体轮廓均匀一圈 → 缩放不一致（对比没 1:1），不是模型问题
- 蓝集中在某一件 → 那件被上层盖住了，回查 draw order
- 全图平均差被大面积抗锯齿边缘稀释，**判某处改对没看该区红像素数的变化**

**三个假源，缺一个屏蔽就会把结论搞反**：

| 假源 | 症状 | 消除 |
|---|---|---|
| 分辨率不一致 | 「多件」凭空多出六到七万像素，看着像整身错位 | 原生尺寸截，`canvas.width == model.canvas.width` |
| 页内说明文字 | 脚区差异从 2068 虚高到 27887 | 把含该文案的 `div/p/span` 设 `display:none` |
| **背景色不同** | 原图白底 vs 播放器黑底，背景差恒 200+ | **只在 `both = (原图非白底) & (渲染非黑底)` 上算** |

背景这一条最易漏、后果最大：实测脚区 32490px 里 **90% 是背景**，屏蔽后真实差异只有 **1916px**
——不屏蔽会得出「改了层级反而差了 15 倍」的错误结论，并把自己引回错的排列。
同理「模型有原图没有」必须 `~om & sm`，不然白色背景自己就被算成多出来的内容。

**改完必须看 delta**：结构改动后同区差异只变 0–2px = 没生效（被 `keep_as_is` 覆盖 / 缓存 / 没部署），
回去查而不是继续调参。缓存要用 `Network.setCacheDisabled(cacheDisabled=True)` 关掉，
并 `Page.navigate` 到带时间戳的 URL —— 只 `Page.reload` 时实测文件 MD5 变了、四次截图却字节完全相同。
拼 cache-bust 参数时必须保留 `?nodrive=1`，否则物理开始跑、截到运动中姿态（差异 41597→95829px）。

## 6. z-order：量出来的，不是推出来的

**原画的可见堆叠 ≠ 层的绘制顺序。** See-through 的归属规则是「每个可见像素只归一层」，
所以一层里可能同时装着视觉上在上和视觉上在下的内容。实测原图逐行统计白色(袜) 119px vs 深蓝(鞋) 10px，
看起来白袜全程盖着鞋，直觉结论是「`legwear` 排在 `footwear` 之上」—— **错的**。

| 排列 | 脚区共同区差异 >30 |
|---|---|
| `legwear → footwear`（袜盖鞋，符合直觉） | 3634px |
| **`footwear → legwear`（鞋压袜）** | **1916px** |

做法：两种 order 各 build 一次、各截一张**同姿态**图（`?nodrive=1` + 参数归零）、按区量差异取小者。

**两种互斥排列都被否 = 素材缺层，不是层级问题。** 循环是这样出现的：袜盖鞋被否（「双脚盖过了鞋子」）、
改鞋盖袜又被否（「鞋到了前面、脚腕镂空、脚背后半没了」）。这时停止翻排列，改查「缺失像素在原图是什么」：
实测那 1578px 原图是 rgb(74,73,76) **深灰描边**，See-through 17 层里没有单独拆出来，
所以无论哪种顺序都会缺。挖补不能救（双向互挖 PSD 合成 4007→4856px、单侧挖 footwear 露黑底 32490px）；
正确处置是把两条结构路线交给用户定：①重抠该小块的语义份层；②换更细的拆层粒度。

## 7. 通用后处理与自动拆腿（可复现配方）

以上各条是「逐例踩出来的」，这一节把它们排成一条**任何素材都能跑**的流水线。

### 7.1 后处理：`postprocess_generic.py <seethrough.psd> <原图png> <输出.psd> [--legs <mask前缀>]`

处理顺序（顺序本身有依赖，不要打乱）：

| # | 步骤 | 判据 / 理由 |
|---|---|---|
| 0 | 读层 | `topil()` 尺寸≠画布时按 `l.offset` 贴回全画布 |
| 1 | 清底膜 | `(alpha>0) & (alpha<60)` → 0；一张图能砍 140–210 万 px |
| 2 | 合并 `legwear+footwear → legs` | alpha 取 over 并集，**RGB 直接取原图**（除零会出黑块） |
| 3 | 补洞 | 只补「腿层附近」：`binary_dilation(core, iterations=8)`；全画布补会把整个人物塞进腿层（实测 374,055px，而人物总共 425,781px） |
| 4 | 颜色换回原图 | 只换 `\|本层RGB−原图\| ≤ 60` 的像素；再兜底「本层近黑但原图非黑」 |
| 5 | 兜底 backdrop | 原图非白 & 所有层未覆盖 & 连通域≥60px |
| 6 | 拆腿（可选） | 用 `--legs <前缀>`，读 `_legmask_L/_R.npy`，**RGB 取原图**；删除 `legs` 层 |
| 7 | 写 PSD | `PSDImage.new(mode="RGBA")`；**按语义画序**写（先写的在下） |

实测三张图的收敛值：合成差 4.76 / 5.30 / 5.30（后两者为女仆立绘、带背景干扰的设定图）。

### 7.2 自动拆腿：`auto_split_legs.py <split.psd> <原图png> <mask前缀>`

不再手测任何数字，全部从像素结构推导：

1. **逐行测段数**（`min_w=12` 滤掉描边碎点，每行只取最宽的两段避装饰件）
2. **找分叉点**：连续 5 行都是 2 段的第一行；`fork_y − top < 40` 视为「无合并区」
3. **两条路线**：
   · 有合并区 → 上段沿前腿实测宽度切、下段按连通域
   · 无合并区（腿一上来就是两条）→ 直接按连通域
4. **前腿宽度** = 分叉区**左段**宽度中位数（不是单段行，原因见 SKILL.md 第 47 条）
5. **逐行定边界**：
   ```python
   if len(segs) == 2:      # 边界放左段描边之外（亮度<110 的暗像素往右推）
   elif len(segs) == 1:
       mid = (bl+br)/2
       if abs(mid-cx) > FRONT_W*0.5:  split_x = br+1 if mid<cx else bl   # 只有一条腿
       else:                           split_x = min(bl+FRONT_W, br+1)   # 两腿连成一片
   ```
6. **输出保留原始抗锯齿 alpha**：`a01 * mask`，不二值化、不羽化（羽化会让两层颜色掺混 → 视觉融合成一条腿）
7. **后腿向左补 `max(18, FRONT_W*0.35)` px**（补色只补 alpha，内容取原图）

自检输出三行，任一异常就回头查：`画面左腿/右腿 px 数`、`重叠 px`、`两腿叠加未覆盖（会露底）px`。
⚠ 「叠加 <0.99」这个数字**要用「低于原 alpha 0.1 以上」来判真漏**，否则会把本来半透明的抗锯齿边全算成漏
（实测 2109px 报告里只有 7px 是真漏）。

### 7.3 绑定：`build_iki_generic.py <split.psd> <输出.iki> [模型名]`

枢轴全按 bbox 推导，不写死坐标：
`back hair / front hair / bottomwear / tail / leg_*` = **bbox 顶部中心**；
`ear_L` = bbox **右端**上沿（贴头那侧）、`ear_R` = bbox **左端**上沿；
`def_Head` 由 neck 层推导、`def_Body` 由 bottomwear 推导。

画出 16–18 parts / 6–8 deformers / 4–6 physics。物理验收（40 帧）：
尾 ±12 / 前发 ±3.5 / 后发 ±3.2 / 裙 ±2.8，尾-前发 r≈−0.17、尾-裙 r≈−0.10 ⇒ 各走各的节奏。

**拆腿后的验收两个数一起看**：参数相关 <0.85（真在分头动）+ 分界缝最大连续空白宽度 ≈ 原图（没撑开间隙）。

# 拆层实战规则（按主题汇总）

切层 / 拆腿 / 补洞相关。配套脚本：`pipeline/postprocess.py`、`pipeline/auto_split_legs.py`。

8. **切之前先数连通域：1 个连通域 + 无颜色分界 = 没有可切的结构，任何切线都是我自己画的。**
   判据不止「切口会被什么挡住」，还要先问「素材里到底有没有这个分界」。开工先跑
   `scipy.ndimage.label(alpha>30)` 数一遍（逐层实测表与配方见 `references/layer-splitting-rules.md`）。
   细分只有两种合法依据：**连通域**、或**颜色/语义**；按坐标切（x 直线、每行中点、y 阈值、
   补一道阴影再沿阴影切）一律是几何面，用户会直接点出来：「你裁切的还是以几何面而不是贴着素材裁切导致的」。
   实测 `legwear` 整层只有 **1 个连通域**（43389px, x[578,763]）—— 两条腿从大腿根到脚踝连成一块，
   按 x 切、逐行找中点切、补接触阴影再切，切出来都是「一坨被分两半」外加每条腿各少一块。
   这种层要独立动画只有两条路：**先补画**（inpaint 出两腿之间真实的空隙）把素材变成 2 个连通域、
   再按连通域分离 —— 那是画图不是绑定，必须单独跟用户确认，不能顺手在切层脚本里硬切；
   或者走第 28 条「同一 part 内部 warp 网格分左右」，那条不用补画也不存在错位露缝。
   反过来，切口被什么挡住决定「切了会不会露」：额头/鬓角下层是**脸皮**、后脑下层是**后发** → 不能切，
   切了必露底色，补边也救不了（露的是下一层内容，不是透明）；**大腿根下层是裙摆、且裙下沿 y 高于切口** →
   即使可切也看不见缝。先判定再动手，能省掉好几轮「拆了→露缝→合回去」。

14. **按颜色拆同一层：边界必须沿用原 alpha，两个 mask 严格互补；能整层调 order 就不要拆。**
    拿 `binary_opening/closing` 清颜色 mask 会改动边界像素，`~mask` 补不回原样，接缝两侧各丢一点
    alpha —— 渲染出来是「胳膊上一条拼缝」，用户一眼看到并直接点名。守则：mask 只用来分区着色，
    alpha 一律 `alpha_out = alpha_src`，并 assert `mask.sum() + (~mask).sum() == (alpha_src>0).sum()`。
    决策前先量重叠：实测 `围裙∩手` 只有 268px（可忽略）、`围裙∩袖` 3698px（本来就该被盖）——
    「必须被盖住的部分」占比很小时，整层前移既盖上袖子又保住手，且结构上不可能有拼缝。

20. **用户说「这些东西应该是一个整体」时，优先合并图层而不是调 z-order。** 腿部实测：
    `legwear` 与 `footwear` 两种排列都被否（袜盖鞋→鞋带被吃 3634px；鞋盖袜→脚腕露洞 1916px），
    用户直接裁定「腿 脚 鞋应该视为一个整体图层」。合并成一个 part 后不存在遮挡关系，
    结构上就不可能再出镂空/错位。做法：`alpha` 取两层 over 并集（保留各自抗锯齿），`RGB` 取原图。
    并集若漏像素（实测缺 8212px），补的时候**必须限制在并集附近**——直接撒整个 bbox 会把裙摆
    一起吞进来（实测面积从 53k 涨到 227k）。

21. **按颜色拆出的层必须按连通域再筛一次，否则会把邻近的同类白色吞进来。**
    实测围裙按「白+低饱和」抠出后有 **4 个连通域**：44355px y[582,821] 是真围裙，
    另三块 7353+2752+1953px 落在 y[422,553]，是**衬衫领口的白色荷叶边**。
    它们跟着 `def_Skirt` 摆、又排在 `topwear` 之前，就把领口盖住了（用户：「衣服上有一点小瑕疵」）。
    修法：只保留**最大连通域**，其余归还原层（实测领口差异 1754→16px）。

22. **按连通域「圈出某个部件」这一步，先确认它没把整层连成一块。** 实测 headwear（白色蕾丝头饰
    + 两侧耳朵）在 alpha 上是**一整块连通域**，用 `np.isin(lbl, 与种子连通的块)` 圈耳朵会把整层都算进去：
    挖空 38666px > 层自身 37832px，直接把 headwear 挖没，build 报 `!! 缺 headwear`。
    正解：以部件特征色为种子，只取**种子 N px 半径内**的像素（`binary_dilation(seed, 17x17) & alpha`），
    再 closing 补缺口、小范围 dilation 吃抗锯齿。这样只圈到部件本体 + 绒毛边，不伸到邻近部件。

24. **给某层补 alpha 时，补块矩形不能竖切进上面的件。** 实测为修「鞋面半透明」把 legs 的 alpha 补成
    `[740:1215, 520:800]`，起点 740 正好切进围裙（围裙 y 到 821）—— legs 带着原图颜色盖到围裙上
    （legs∩apron = 7646px），围裙边缘出现重影/黏连。修法是起点放到所有上层件的下沿之下（改 880）。
    补之前先查「该矩形与每个上层件的 bbox 重叠多少」。

25. **两种互斥排列都被用户否掉时，问题在素材粒度，不在层级。** 会出现这种循环：袜盖鞋被否
    （「双脚盖过了鞋子」）、改成鞋盖袜又被否（「鞋到了前面、脚腕镂空」）——两种都错说明**层里缺东西**。
    这时不要再翻第三种排列：把两种的区差异数字摆出来（1916 / 3634）、把缺失像素的**原图颜色**查出来
    （实测那 1578px 原图是 rgb(74,73,76) 深灰描边，See-through 没单独拆出来），然后给两条结构路线
    让用户定：①重抠该小块的语义份层（范围明确、可用 PSD 合成差异验证）；②换更细的拆层粒度。
    试过的挖补全部记成死路（双向互挖把 PSD 合成搞差、单侧挖 footwear 露黑底），不要当方法复用。

28. **单连通域的肢体、又不许补画时，第三条路是「同一 part 内部用 warp 网格分左右」。**
    不拆 part，给该件一个较密的 warp 网格，左半列绑 `LegL`、右半列绑 `LegR`。因为是同一个 part
    的网格形变，不存在两个独立矩形相对错位，结构上不可能露缝；代价是只有网格级形变、没有各自独立枢轴。
    它比补画省事（不破坏原画质感）、比几何硬切安全（用户已明确否过几何切）。
    ⚠️ **本机尚未实测**，动手前先自检三条：①打印每列的角色像素数，中间列接近 0 才说明两腿在网格里
    真占到不同列；②网格密度至少覆盖到两踝间距的一半；③绑完用 `scripts/measure_underlayer_leak.py`
    对中间缝做一次露底统计，摆动帧不得高于静止帧。三条中有一条不过，就回到「整块小幅摆 + 明说上限」。

29. **「矩形分离」的真因：拿中线当边界。要找前腿在分叉处的真实右边界。**

    实测前腿真实右边界 x≈645–650，而「髋中点→膝中点」中线在 x≈679 ——
    多出来的 30px 就把后腿的一部分划给了前腿（用户：「左边的腿附带了右边的腿的一部分」）。
    做法：在**真分叉行**读 `segs[0][1]`（前腿右边界），向上逐行延伸；
    合并行用「合并块中点 − 5px」近似。

    三个必须排除的干扰：
    · y 890–940 也是「2 段」，但第一段是**尾巴**（x 520–563）—— 不排除就会把尾巴右边界当腿边界
    · 「合并→分叉」是**渐进**的（间隙 1px→8→15→20），阈值至少 8px；用层边界并集当基准时会出现 1px 假缝
    · 上/下段之间不能漏行：上段取到 fork_y−1、下段从 fork_y+2 起 ⇒ y=989/990 两行无人区，
      渲染出来是一条**水平白线**（用户：「双腿袜部出现水平白线切割/错位」）。下段直接从 fork_y 起。

    后腿在重叠带里的内容要用**它自己的像素横向填实**，不要留着前腿的像素 —— 否则摆腿时拖出前腿的边。

30. **numpy 广播能静默吃掉你所有的边界计算——切分前必须先做「左端/右端一致性」自检。**

    连改 12 版都没修对腿的根因不是参数，是这一行：
    ```python
    xx = np.arange(W)[None, :]      # (1, W)
    split_x                          # (H,)
    m_front = upper & (xx <= split_x)   # ← 广播成 (1,W) vs (1,H)
    ```
    两边按**最后一维**对齐，于是变成「第 x 列 比 split_x[x]」——拿第 x 行的边界判第 x 列的像素，
    **行列完全错位**。而且不报错，只是边界永远不生效。

    **症状特征：**调参完全无反应，某个方向被钉在一个固定值上（这里前腿右端恒为 650）。
    **发现方式：**在赋值后立刻打一行自检，把「设计值」与「实际结果」并排比：
    ```python
    for _y in (800, 820, 900):
        print("y=%d split_x=%d m_front右端=%s" % (_y, split_x[_y], np.nonzero(m_front[_y])[0].max()))
    ```
    实测输出 `split_x=675  m_front右端=650` —— 两者矛盾就说明运算没按预期广播。
    **修法：**`split_x[:, None]` → (H,1)，再与 (1,W) 广播成 (H,W)。
    推到同类：只要把「一维逐行数组」和「二维坐标网格」混用，就必须写成 `arr[:, None]`。

31. **legs 层里往往混着裙摆，切分前先确定「真腿从哪一行开始」。**

    `legs` 从 y=754 就有 alpha，但实测原图：
    ```
    y=820  x=675 → (8,9,15)      近乎黑（裙摆暗部）
    y=880  x=675 → (255,255,255) 纯白（衬裙）
    y=910  x=686 → (236,188,175) 肤色  ← 真腿从这里才出现
    ```
    在 y 754–900 切分，分界线正好穿过裙摆的深色边，渲染出来就是用户说的
    「一条从裙摆下方一直延伸到大腿、袜口及袜筒处的黑色线条」。
    正确做法：**裙摆段(y<900) 整段归前腿，只在真腿段切**。后腿也不需要那一段——它被 bottomwear 盖住。

32. **补色取样必须跳过描边，否则整条重叠带被刷成黑线。**

    取「后腿最左可见像素」当填充色时，那一列正是**描边**（实测 y=1000 后腿左界 x=666 是 (55,55,56)）。
    结果整条 10px 重叠带变纯黑 — 又一条黑线。
    做法：从最左可见列往右跳过亮度<110 的连续暗像素，取第一块亮像素作色。

41. **See-through 每层都带一层「底膜」：alpha 1–60 铺满全画布，必须清零，不是抬满。**

    ```
                  alpha 1-60 的像素     真实内容（alpha>200）
    mouth             1,520,597              1,259
    eyewhite          1,252,128              4,399
    face（另一张图）    878,744             16,422
    ```

    这层底膜叠上去让整张画面发亮（合成差 21→5.3 就是砍掉它之后的差）。
    **处理：`alpha < 60` 一律置 0。** 真实轮廓的抗锯齿通常 >100，砍 60 以下不伤边缘。
    ⚠ 这与另一条「半透明雾要抬满 255」不冲突、但对象相反：
    **1–60 是底膜→清零；61–254 且落在主体内是边缘→抬满**。先按 alpha 直方图分段再决定动哪一段。

42. **See-through 会整块漏掉内容 —— 必须加一张「画序最底」的 backdrop 兜底层。**

    实测某块裙子（x[668,689] y[1100,1140]）**所有层 alpha 全 0**，拆腿后直接露出白背景，
    表现为「两腿之间有个白洞」。修法：原图非白 & 任何层都没覆盖 → 收进 `backdrop` 层，画序排第一。
    补完合成差 6.47→5.30。零星噪点按连通域面积 ≥60px 过滤（JPEG 在白底上的脏点）。

    同一段管线还有两个会炸／会出黑块的坑：
    · **层 `topil()` 尺寸不等于画布**（可带 offset 或被裁切，实测某层 1230×757 vs 画布 1280×1280）
      → 直接当画布会 `operands could not be broadcast`。必须按 `l.offset` 贴回全画布。
    · **合并层时 `p/out_a` 在 alpha 极低处算出 (0,0,0)**，而「颜色换回原图」的容差 60 够不到
      （黑 vs 蓝白差 150+），黑块就留在纹理里（实测 2323px 纯黑块）。
      两道修：合并后 RGB 直接取原图 + 通用兜底「本层近黑(≤15) 但原图非黑(>40) → 取原图」。

43. **写 PSD 的层序按语义画序排，不能按面积排。**

    想当然地「面积小的在下面」会把裙子盖到脸上、头发盖住眼睛 —— 实测合成差 28.03 vs **5.30**。
    画序表：`backdrop → back hair → tail → legs → neck → bottomwear → handwear →
    apron_top → topwear → headwear → ears → face → nose → mouth → eyebrow → eyewhite →
    irides → eyelash → front hair`。表外的层补在最上面。

44. **背景有渐变／文字／其他头像框时，先抠出中间那个人物再拆层。**

    本机可用 ComfyUI `LayerMask: RemBgUltra`（RMBG-1.4）。三个坑：
    · `process_detail=True` 直接报 `cannot import name 'fix_trimap' from 'pymatting'` → 设 `False`
    · **`SaveImage` 存 RGB 会丢 alpha**，看起来「什么都没去掉」；要另接 `MaskToImage` 导 mask
    · GroundingDino+SAM 在这里不好用：prompt 宽泛时框把整个画面选进去（前景占 78.8%），
      且它的 image 输出只有 3 通道，接 `ImageToMask(alpha)` 直接 `index 3 is out of bounds`
    抠完按连通域面积剔碎片（实测 84 块零散白点共 10218px，阈值 3000px），再裁 bbox 居中放白底。

46. **层名归一化不许吃掉 `leg_L` / `ear_L` 这类左右成对层的下划线。**

    把 `leg_L` 归一成 `leg l` 后匹配不到 deformer 表，症状是**腿完全没动画**，而 parts 数量正常、
    不报任何错。归一化前先把成对层名映射回带下划线的形式。

47. **自动拆腿：`FRONT_W` 用「分叉区左段宽度中位数」，不要用「单段行」的宽度。**

    单段行往往只剩鞋底那几行（实测只有 3 行），算出 37px 而真实腿宽 76px —— 底部两鞋靠在一起时
    就会整块判给一条腿。另外**单段行要分两种情况**：明显偏左/偏右 ⇒ 只是其中一条腿存在，整块归它；
    横跨中线且够宽 ⇒ 两腿连成一片，按 `FRONT_W` 切。漏掉这个判断会把「只有右腿的那几行」划给左腿。

    完整判定流程（分叉点、有无合并区、描边外侧边界、抗锯齿 alpha 保留）见
    `references/layer-splitting-rules.md` §7。
