# 层缝：单图自动切层的硬上限与量化

## 结论先写

单图切层出来的层是**像素硬切、层间没有重叠**。手工 Live2D 的做法是每层边缘往外多留 2–4 px
互相盖住，所以怎么动都不露底；自动切层做不到，任何变形都会在层与层的交界处透出背景。

所以「明显撕裂 / 选区空隙」在这条管线上**不是 bug、也不是绑定参数没调好**，是素材形态决定的。
两步走：**① 收幅度（只能减轻）；② 切完给层补边（alpha 外扩，能把缝压到 0.0x%）**。
第 ② 步是纯算法、不需要 AI、不需要分层素材，实测有效——先做它，再谈降幅度。

## 怎么量（可复现）

1. 播放页把背景刷成洋红（`document.body.style.background='magenta'`，`#stage` 也刷）：
   画布是 `clearColor(0,0,0,0)`，任何没有层覆盖的像素都会透出洋红，肉眼立刻可见。
2. 每个姿态截图后立刻另存（`capture_screenshot()` 每次返回同一路径，连拍会覆盖）。
3. `scripts/measure_gaps.py rest.png pose.png` → 以 rest 的实心区为基准，统计 pose 里变洋红的像素。
   判据要**先腐蚀 rest 一圈**再比，否则转头时角色整体位移会把轮廓外缘算成「新露出的缝」。

## 实测（同一张 Q 版全身立绘，1100 画布，取 1000×1000 渲染）

| 版本 | 转头 X=30 | 闭眼 | 张嘴 1.0 |
|---|---|---|---|
| 原版（profile 默认幅度） | 2.00% | 0.59% | 0.46% |
| 软幅度（turn 0.65 / hair.follow 0.85 / hair.sway 0.6 / eyes.blink 0.55） | **1.16%** | 0.54% | — |
| 软幅度 + 左右鬓发独立成层 | 1.85% | 0.33% | — |
| 过保守（turn 0.35 / sway 0.4 / blink 0.45） | 1.02% | 1.05% | 0.92% |

读法：
- **软幅度是这组的均衡点**（转头降 42%）。
- **给 `sideHair` 不一定更好**：闭眼变好（0.33%）但转头恶化（1.85%），因为侧发层自己也移动、
  自己会裂。要试就单独量，别默认它更优。
- **`eyes.blink` 不能压太低**：降到 0.45 时闭眼只合一半，反而露出更多（1.05% vs 0.54%）。
  眨眼要的是「合得上」，不是「动得小」。

## rigPlan 旋钮与 clamp

`autoRigFromLayers({rigPlan})` 可用字段（`describe_rig_plan()` 全量列出，含 range/recommended）：
`turn.amount / featureLead / eyeForeshorten / noseLead / farEar`、`hair.follow / outlineFollow / sway`、
`eyes.blink`。

实测会 **clamp**：`frontHairWidth > 1`（刘海比脸宽）时 `turn.amount` 被压到
`0.4007`（请求 0.65）甚至 `0.2055`（请求 0.35），`rigPlan.clamped` 会写明。想真放大转头幅度，
只有先收窄 `frontHair` 重切 —— 而收窄会露缝，等于两个目标互相拉扯，选一个并告知用户。

## 修法：alpha 外扩（把缝从 2.00% 压到 0.04%）

手工分层「每层多留 2–4 px」可以机器近似：切完层后把每层的 alpha 往外扩几像素，
并把扩出来的区域用邻居颜色填满（不填就是一圈黑/透明脏边）。

```python
# extend_layers.py <src_dir> <dst_dir> [grow]   —— 见本工程，逻辑只有三步
rgb, a = im[:,:,:3], im[:,:,3]
known = a > 8
filled = fill_rgb(rgb, known)        # ① 透明区用 8 邻域均值反复扩散填 RGB（3–4 px 约 20 轮）
al = grow_alpha(np.where(known,255,0), grow)   # ② alpha 做 grow 次 3×3 最大值滤波
im_out = dstack([filled, al])        # 画布尺寸/文件名不变，autoRig 靠文件名认槽位
```

实测（同一张图、软幅度 rigPlan、1000×1000 渲染）：

| 层处理策略 | 转头 | 闭眼 | 张嘴 | 静止态膨胀 |
|---|---|---|---|---|
| 不动 | 1.16% | 0.54% | 0.46% | 0.35% |
| 全层 +3px | **0.04%** | **0.00%** | **0.00%** | 6.14% |
| 只扩大面层 +4px | **0.08%** | **0.00%** | **0.01%** | 7.02% |
| 只扩内层（轮廓层不扩） | 1.27% | 0.62% | 0.73% | 0.46% |

四条硬结论：
- **轮廓层必须一起扩**。漏掉 `hair_back` / `body` 时露底反而更差（1.27% vs 1.16%）——
  缝隙主要在「轮廓层外缘 × 内部层」的交界，轮廓边缘不扩等于没修。
- **细节层不要扩**：`iris_*` → 虹膜变大发糊；`lash_*` → 睫毛变粗；`mouth` → 嘴变肥
  （嘴只有约 900 px，+3 px 就涨 68%）。扩 `face` / `body` / `hair_front` / `hair_back` / `eye_L` / `eye_R` 就够。
- **`eye_*` 扩会让眼白大几像素**：Q 版大眼看不出来，写实比例的脸要单独量。
- 代价是**轮廓整体变粗**（+4 px ≈ 角色面积 7%）。贴纸描边风格几乎不可见，细线稿风要谨慎——
  给用户对比图让他自己判，别替他拍板。

**补边的质感也很重要（用户会直接指出“裂缝换成边缘模糊”）**

v1 的两个错让缝变成了「粗糙」：① 颜色用 8 邻域**均值**扩散 → 那圈颜色被平均成一圈发白的尸带；
② alpha 只用 3×3 最大值滤波 → 阶梯状硬锯齿。正确做法（`extend_layers_v2.py`）：
颜色改为 **4 邻域复制最近像素**（原色直接延伸，锐利），alpha 扩完后**只羽化新增那圈**
（原层内部边缘不动，否则原图的锐边也糊了）。

| 版本 | 转头露底 | 静止膜胀 | 边缘锐度（拉普拉斯均值，越高越锐） |
|---|---|---|---|
| 原版（有缝） | 2.00% | 0.00% | 6.91 |
| v1 均值填充 +4px 硬边 | 0.08% | 7.02% | 7.09（硬锯齿、发白） |
| **v2a 复制 +2px 羽化 0.8** | **0.06%** | **5.31%** | **6.91**（与原版持平 = 没引入模糊） |
| v2b 复制 +3px 羽化 1.0 | 0.16% | 6.33% | 6.89 |
| v2c 复制 +2px 无羽化 | 0.43% | 5.18% | 7.29 |

结论：**2px + 复制填充 + 0.8 羽化是甜点**（抖底 0.06%、膜胀只有 5.3%、锐度不变）；
3px 以上开始回退（露底反而升、膜胀变大），无羽化则目视毛边明显。验证时可把轮廓区
放大 2.5× 左右对比给用户看——整图缩小看不出这层差别，他会以为没改。

**轮廓层扩出来的那圈必须填「描边白」（最容易返工的一条）**

给所有层都做颜色扩散时，最外层轮廓（`hair_back` / `body`）扩出的环取的是内部发色/衣色，
落在**白描边外面就成一圈杂色**——用户的原话是「本身的边缘没事，而是白色边缘外围多了一圈杂色」，
拿放大对比图也看不出来，因为他看的不是层缝。正确做法：

```python
KNOWN_OUTLINE = {"hair_back.png", "body.png"}   # 只认这两个，别用「面积最大的两层」
if name in KNOWN_OUTLINE:
    filled[ring] = 255                       # 扩出的环强制填白 = 描边加宽，视觉自然
else:
    filled = spread_rgb_copy(...)            # 内层仍用复制 + 羽化
```

- **判轮廓层不能用「alpha 面积最大的两层」**：刘海面积可能大于身体，判错会给刘海扩一圈白，
  压在脸边上变白线；按文件名点明 `hair_back` / `body`。
- 实测白边外那圈：杂色占比 **89.2% → 30.1%**，环内平均色 RGB(236,209,225) 粉紫 → (248,240,247) 近白。
- 残留那 30% 是两个来源：内层扩出的像素溢出到大轮廓之外；羽化让边缘半透明、混背景成淡色。
  要更干净得把内层外扩结果裁回原 silhouette 之内。

## 什么时候才算真解决

外扩消掉的是「层间缝」（能到 0.0x%）；消不掉的是「**该有的内容根本不存在**」：没有 lip set 时的
口腔、侧脸的内耳、被头发完全遮住的那片皮肤。这类只能靠生成式拆层。

**实测过的生成式拆层工具：See-through**（SIGGRAPH 2026，`shitagaki-lab/see-through`）

部署位置自选（独立 venv，与 ComfyUI 隔离），
完整命令与验收记录见该目录 `00_执行文档.md`。用之前必须知道的三件事：

1. **它重画，不搬像素**。输出层是 SDXL 重建的：角色认得出来、结构对，但眼高光、缎边、碗筷这类细节会糊，
   手/道具会粘连。**角色区域内 SSIM 0.938**（全图只有 0.76，因为 PSD 没背景层，`composite()` 把透明处
   变黑——评保真必须在角色 mask 内算，否则会把好结果看成不及格）。
2. **分辨率必须给 1280**（模型训练分辨率）。同一张 1024 图：1280 推理角色区 0.938，1024 推理 0.907，
   全图 SSIM 更是 0.76 vs 0.49。别为了“贴合原尺寸”而用 1024。
3. **遮挡补画不是 fully inpainted**。像素硬检验（用 `front hair` 的 alpha 反查 `face` 层）：
   刘海覆盖区里只有 **54.1%** 的像素在 `face` 层上真有皮肤，另 45.9% 是挖空的；`eyelash` 下的
   `eyewhite` 只补了 36%。比自动切层（0%）强，但别按论文宣传的“全补”去期待。Q 版/非常规比例更明显。

它给的层名是标准拆件目录：`back hair / front hair / face / eyewhite / irides / eyebrow / eyelash /
mouth / nose / headwear / topwear / bottomwear / legwear / footwear / handwear / neck / objects`，
层序即深度序，可以直接按槽位映射（成对层按 x 中位线切成 _L/_R，服装类合并成 `body`）。
资源实测：1280/30 步 layerdiff 5:56（11.8 s/it）+ 深度约 4 分钟 ≈ 12 分钟/张，峰值显存 18.5GB/20.5GB
（`--group_offload`，20GB 卡能跑，ComfyUI 占着 6.9GB 也撑住了）。

**推荐的两条腿结合**：See-through 出层的 alpha 形状 + 原图填颜色（纹理贴回），既不缺内容也不掉细节；
纯靠 See-through 的生成图会糊，纯靠自动切层会缺内容。

### 纹理贴回的致命细节：补画区不能用原图色

把“原图颜色”整层贴到生成层的 alpha 上，会把**别的部位贴进来**。实测：face 层 106,522 px 补画区里
原图是刘海（均色 RGB 87,100,151 深蓝），而模型生成的是肤色（229,191,192）——全贴原图后，
脸层里 **60.75%** 的像素是头发色，脸和前发就“长在一起”了（正是撕裂/层内容互混的同一个病）。

正解：**按像素来源分区贴**——原图在该像素本来就能看到该层内容（如 face 层里是肤色）才用原图色；
被遮住的补画区必须用生成色。边界用 2px 高斯权重过渡，不要硬接。

```python
skinish = (r > 150) & (r > g) & (g > b) & (b > 120)     # 按层语义定判据（face=肤色）
w = ndimage.gaussian_filter(skinish.astype(np.float32), 2.0)[..., None]
mix = O * w + L[:, :, :3] * (1 - w)                     # 可见区取原图，补画区取生成
```

验收指标：修前该层内“偏蓝(头发色)”像素 85,648（60.75%），修后 **0 个（0.00%）**。
每次贴回都要用这类色调统计回验，不要只看缩略图——缩略图上看不出来，放大就露餍。
对用户就这么讲：**缝能靠算法补到看不见；缺的内容要么给分层素材，要么上 See-through 重新拆一遍。**
