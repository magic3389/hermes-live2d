# 已知问题与可修性

这份清单是**跨素材反复发生**的问题账，不是单次调试记录。
每条给：现象 / 判据 / 修法 / 可修性。末尾是给后来者的硬规则。

---

## 0. 共同根因：单图语义分割不是 3D 补全

一条最省事的记忆：**原图上没有的像素，任何后处理都变不出来。**

See-through 做的是「按颜色纹理把一张图分给若干层」。它不知道：

- 这块布属于同一条裙子（只按颜色纹理分）
- 腿挡住的尾巴背面是什么样（原图被挡住了）
- 后裙摆该在腿后、前裙摆该在腿前（只给一个 `bottomwear`）

于是「分层 / 残缺 / 露洞 / 切割感」这四类抱怨，根子都在这里。
它们不是绑定器写错了，是**输入信息量的上限**。

## 一、可自动修（后处理规则已覆盖）

| 现象 | 判据 | 修法 | 入口 |
|---|---|---|---|
| 裙子一半动一半不动 | 裙子几何区内两层像素接近对半（实测 20,163 vs 20,168） | 非裙子层在该区内容**并回** `bottomwear` | `--skirt-zone y0` |
| 尾巴上有「腿的痕迹」 | 先量 `tail ∩ legs` 的颜色族：**冷色是本体的蓝，暖色才是错分** | 只挖暖色那部分（实测 21,427px 里只有 1,437px 该挖） | §2.12 |
| 胳膊「透明 / 没了」 | 袖子像素挂在裙子 deformer 上，静态差分 **0** | 按肩→腕解剖锚点划带，带内 `bottomwear` 浅色挖掉 | `--sleeve-band x_sh,x_wr,y0,y1,half` |
| 袖子里的深色描边消失 | 挖空后该处显示后层发色 | 带内 `ref.min<145` 补进 `topwear`，alpha=255 | §2.10 |
| 腿边/鞋尖深色杂色块 | 层在自己**不透明**处带错色，原图该处明显更亮 | 色差>90 **+ 排除冷色**（`B<=R+15`）+ 原图更亮>55 | §2.6b |
| 某块发暗 / 像丢了 | `0<alpha<250` 且层色与原图差>40 | alpha 抬满 + RGB 取原图 | §2.6 |
| 手/手持物被衣服盖、杯子悬空 | `handwear` / `objects` 画序排在 `topwear` 之前 | 改 `ORDER`，把两者压到 `topwear` 之后 | `build_iki.py` ORDER |
| 腿脚「没动」 | deformer ±3px + physics `scale 8` ⇒ 参数只到 ±0.06 | `translateX ±9` + `scale 38` ⇒ ±1.95（≈17px） | deformer + physics |

## 二、方法学限制（不要答应「修好」）

### 2.1 被遮挡部位无法补全 → 只能限制幅度

尾巴在腿后面、长发盖住尾巴或身体：**原图那里没有像素**。
部件一摆出原位就露出空洞，用户会描述成「残缺 / 没补全 / 有腿的痕迹」。

**唯一可控的解：物理幅度 ≤ 遮挡余量。**

```
尾巴 ±24°、长约 300px ⇒ 末端横移 sin24°×300 ≈ 122px ⇒ 必露洞
收到 ±10° ⇒ 末端 ~52px，牵连降到 2,469px
```

替代路线（幅度不够用时）：
1. 让被遮部件绑成遮挡部件的子级，跟随运动（「它本来就在后面」成立）
2. 人工补画遮挡区（成本高、效果参差）
3. 出图时就摆成分开姿势，从源头避免遮挡

### 2.2 整条裙子一个图层 → 物理上不可能同时在腿前又在腿后

真实穿着：后裙摆 order < 腿，前裙摆 order > 腿。
See-through 只给一个 `bottomwear`（实测 291,960px、bbox 撑满画布）⇒ 后裙摆盖住腿脚。

**必须人工劈成 `skirt_back` + `skirt_front` 两片。**
自动劈分只能靠几何（腿 bbox 中线 + 裙摆轮廓），在「腿被裙摆盖住大半」的素材上不可靠。

### 2.3 坐姿 / 交叠腿不能自动拆

判据（跑之前先量，别跑完再后悔）：

| 指标 | 站姿分开（可拆） | 坐姿交叠（不可拆） |
|---|---|---|
| `legs` bbox 宽 / 画布 | 19% | **75%** |
| 左右像素比 | 1.07 | **1.9** |

**左右比 >1.5 或 bbox 宽 > 画布 50% 就不要拆**，用整块 `legs` 小幅摆，交付时明说「腿不独立动」。

验拆对没看 `(L&R).sum()` 重叠像素（正确时仅几十 px），**不要看黑底 vis 图**——VLM 会把轮廓锯齿读成「绿色侵入左腿」。

### 2.4 没有 `legs` 层

腿被长袜/裙子盖住大半时，See-through 只给 `legwear`，没有 `legs`，无从拆。

## 三、warp 与 matrix：不是参数差别，是能力差别

| deformer | 结构 | 能做什么 | 用在 |
|---|---|---|---|
| `kind:"matrix"` | pivot + translate/rotate/scale | **整体刚体** | 头部、身体、四肢整体 |
| `kind:"warp"` | 控制点网格 + 逐点 offsets | **逐点弯曲** | 裙子、尾巴、长发、布料 |

**只写 matrix 的傀儡不是 Live2D，是会平移的贴图。**

三个必守点（每个都实测翻车，完整配方见 `skill/2d-puppet-rigging/references/warp-deformers.md`）：

1. **网格覆盖整个 part**，只盖下半段 ⇒ 上半段不参与变形，和下层叠成「一层动一层不动」
2. **keyform 的 `value` 必须是参数的 own-range 值**（不是归一化）；写死 −1/0/1 而参数是 −8..8 ⇒ 只走 1/8 量程，位移肉眼为 0
3. **网格密度决定切割感**：4×4 / 749px 宽每格 190px，线性插值折出硬棱；**10×10**（每格 75px）才是连续弧

## 四、给后来者的五条硬规则

1. **语义层名 ≠ 几何分组。**
   `topwear` 里可能有裙子，`back hair` 里可能有白袖子，`handwear` 里可能有裙摆。
   绑定器按层名挂物理，所以「同一件衣服被劈进两个物理系统」是常态。

2. **判断像素归属必须用原图色，不能用层自己的 RGB。**
   See-through 已把错分区域涂成目标层颜色，用层色比较**恒为 0**，规则会一次都不触发、还不报错。

3. **物理幅度 ≤ 遮挡余量。**
   被遮 W 像素宽，位移不能超过 W，否则必露洞。这不是调参能解决的。

4. **功能排斥 mask 必须按解剖锚点核过范围。**
   袖带 y 上限写到 820 而手腕在 589 ⇒ 整段裙摆被「保护」起来没归并。
   **跑完必须回数目标区残留**（该层在区域内应接近 0）。

5. **静态像素差不能证明「修好了」。**
   静态可以与原图逐像素差 0，而动态仍分层、露洞、跟错层摆。
   验收必须给**驱动到满量程后的两帧差** + 「外轮廓到底动没动」。
