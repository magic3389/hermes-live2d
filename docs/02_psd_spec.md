# 给美工的分层 PSD 交付规范

> 版本 v1.0 ｜ 适用：2.5D 立绘自动绑定（Anime2.5DRig / StretchyStudio / PNGAL 均按此规约读取）
> 你只负责**画**和**分层命名**，绑定、物理、眨眼口型由程序自动完成。

---

## 一、一句话说明

提交一个**分层 PSD**，层名按下面的表命名，程序就能自动把它变成会眨眼、会张嘴、会摆头、头发会飘的 2.5D 角色。
**层名错了就等于没交**（程序退化成"整张图跟着晃"），所以请优先看第二节的命名表。

---

## 二、画布规格（硬性要求，不符合会被退回）

| 项目 | 要求 | 说明 |
|---|---|---|
| 文件格式 | **PSD**（不要 PSB、不要 TIFF 套 PSD 后缀） | 程序只解析 PSD |
| 色彩模式 | **RGB / 8bit** | 16bit、CMYK、灰度都会被拒 |
| 文件大小 | **≤ 128 MB** | 超了就拆成两份交，或删掉隐藏层后另存 |
| 画布 | **正方形**，边长 **768 ~ 2048 px**（推荐 1280 或 1536） | 非正方形会导致定位偏移 |
| 图层 | 必须是**真正的图层**，不能是图层组里的智能对象 | 智能对象要栅格化 |
| 隐藏层 | **提交前删掉或展平** | 隐藏层不读，但会占体积、拖慢加载 |
| 背景层 | **不要背景**（透明底），或单独一层命名为 `bg` | 程序自动跳过 `bg` |

---

## 三、层命名表（核心）

命名规则很宽容：全角/半角、大小写、`_` `-` 空格、`のコピー` / `copy` 后缀，程序会自动规范化。
**但层名必须能对上下面任意一个名字**（英文或日文别名都行）。

### 3.1 必须画（缺了角色就"不动"或"缺件"）

| 层名 | 日文别名 | 内容 | 备注 |
|---|---|---|---|
| `face` | 顔、輪郭 | 脸部底色（皮肤 + 腮红） | **唯一绝对必须**，所有锚点以它为准 |
| `eyewhite` | 白目 | 眼白（左右可以画在同一层） | 程序自动左右分离 |
| `irides` | 瞳、黒目 | 虹膜/眼珠（左右同层即可） | 会做视线移动、缩放 |
| `eyelash` | まつ毛、アイライン | 睫毛/眼线（睁眼状态） | |
| `eyebrow` | 眉、眉毛 | 眉毛（左右同层即可） | |
| `mouth_open` | 口、開き口 | 张口的嘴 | 叫 `mouth` 也行，程序自动改名 |
| `front hair` | 前髪、bangs | 刘海 | 有独立物理摆动 |

### 3.2 建议画（不画程序会自动生成，但手画更好看）

| 层名 | 日文别名 | 内容 | 不画会怎样 |
|---|---|---|---|
| `eye_close` | 閉じ目 | 闭眼状态（左右同层） | 程序用内置闭眼素材缩放贴合，**可能和你的画风不搭** |
| `mouth_close` | 閉じ口 | 闭嘴状态 | 同上，用内置素材凑 |
| `eye_close2` | 閉じ目2 | 第二种闭眼（可选） | 20% 概率长闭眼用，没有就只眨普通眼 |

### 3.3 按需画（有专门效果）

| 层名 | 日文别名 | 内容 | 效果 |
|---|---|---|---|
| `nose` | 鼻 | 鼻子 | 跟随头部 |
| `ears` | 耳 | 耳朵 | 跟随头部 |
| `earwear` | ピアス、イヤリング | 耳饰 | **会像钟摆一样摇** |
| `eyewear` | 眼鏡、メガネ | 眼镜 | 跟随头部 |
| `facedetail` | 頬、頬染め、blush | 腮红/面部细节 | 跟随脸部 |
| `headwear` | 帽子、髪飾り、カチューシャ | 头饰 | 跟随头部 |
| `side hair` | 横髪、もみあげ | 鬓发/侧发 | 同刘海摆动 |
| `ahoge` | アホ毛 | 呆毛 | 同刘海摆动 |
| `back hair` | 後ろ髪、後髪 | 后发 | 独立物理摆动 |
| `tail` | 尻尾 | 尾巴 | **会摇摆** |
| `wings` | 羽、翼 | 翅膀 | 跟随 |
| `neck` | 首 | 脖子 | 见下方"特别注意" |
| `neckwear` | ネクタイ、チョーカー | 颈饰 | 跟随 |
| `topwear` | 服、上半身 | 上装 | **呼吸、胸部起伏靠它** |
| `bottomwear` | スカート、ズボン | 下装 | 跟随 |
| `handwear` | 腕、手 | 手臂/手 | 有"手臂高度"参数 |
| `legwear` | 脚、靴下 | 腿/袜 | 跟随 |
| `footwear` | 靴 | 鞋 | 跟随 |
| `objects` | 小物、道具 | 手持道具 | 跟随手部 |

### 3.4 头发要分束的话

想让人物头发飘得更自然，就把头发拆成多层并加序号：

```
front hair_1     ← 左侧一束
front hair_2     ← 中间一束
front hair_3     ← 右侧一束
back hair_1
back hair_2
```

**每一层各自独立做物理运算**（每层最多识别 6 束，按层宽自动定）。不拆就只有一整块在晃。

---

## 四、分层原则（决定"动起来好不好看"）

1. **层的边界要藏在遮挡处**，不要切在视觉上明显的地方。
   例：刘海的分界线要在发梢天然的交叠处，不要横穿额头。
2. **每个层都要画"被遮住的部分"**（关键！）
   - `face` 要画**完整的一张脸皮**，包括被刘海盖住的额头、被侧发盖住的颊边
   - `eyewhite` 要画**完整椭圆**，包括被上眼睑/睫毛盖住的部分
   - 服装层要画到被手臂/道具遮住的部分
   - 这一条决定转头时会不会露洞。**宁可多画，程序会按上层遮挡裁掉多余部分。**
3. **层内不要留半透明过渡**（羽毛边缘可以，但不要大面积半透明）。
4. **描边归属**：外轮廓的描边画在**最外层**（`back hair` / `body` 类），内部件的描边跟着自己走。
5. **同一部位的多个件可以合并**：比如左右眼白画同一层没问题，程序按连通域质心自动分左右。

---

## 五、特别注意：脖子这一层

如果同时交 `neck` 和 `topwear`，脖子与身体的前后关系在转头时容易破（接缝会露）。
**推荐做法**：**不单独切 `neck`，把脖子直接画进 `topwear`**（一体型），最稳。

---

## 六、交付前自查清单（逐条打勾再交）

```
[ ] 文件是 PSD，RGB / 8bit，≤128MB
[ ] 画布是正方形，边长在 768~2048 之间
[ ] 所有图层已栅格化（无智能对象、无文字层）
[ ] 隐藏层已删除，图层组已展平（或至少组内层有正确命名）
[ ] 有且只有一个 face 层
[ ] face 层额头部分画完整（不是被刘海挖空的）
[ ] eyewhite 是完整椭圆（不是被睫毛切掉的半张）
[ ] 层名逐条对照第三节的表
[ ] 头发如果要飘，已拆成 _1 _2 _3
[ ] 没有背景，或背景层命名为 bg
[ ] 打开 PSD 时所有图层都是"正常"混合模式（不要用"正片叠底"叠阴影）
```

## 七、常见退件原因

| 现象 | 原因 | 修改 |
|---|---|---|
| 只有脸在动，头发是死的 | 头发全合在一层且没叫 `front hair` / `back hair` | 按 3.4 拆分并命名 |
| 一转头脸上就露洞 | `face` 层是按刘海形状挖空的 | 补画完整脸皮 |
| 眨眼时眼白消失 | `eyewhite` 只画了露出部分 | 补成完整椭圆 |
| 整张图只是一个整体在晃 | 层名全都不认识（图层名是"图层 1""图层 2"） | 对照第三节改名 |
| 颜色发灰 / 有双重影子 | 用了正片叠底之类的混合模式 | 改成"正常" |
| 加载报错或卡住 | 16bit / CMYK / 超过 128MB | 转 8bit RGB、压体积 |
| 脖子处有横向裂缝 | `neck` 与 `topwear` 前后关系 | 合并脖子进上装 |

## 八、参考：AI 自动拆层的 PSD 也能直接用

如果一张成品图想快速出分层，可以先用 See-through 自动拆成 17~23 层（层名符合上表），
**它的输出可以直接导入**，不需要改命名。

但要知道它的局限（我们实测）：
- 被遮挡区域只补了 54%（脸）/ 36%（眼白），不是全部
- 可见区域保真度高（前发与原图相关系数 0.95），细节会略微糊化
- 所以：**AI 拆的适合做原型和验证；正式交付还是手画**
